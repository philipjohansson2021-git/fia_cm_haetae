## 0. 한 줄 결론

실HW 클럭글리치로 **HAETAE 비밀키 s1(768계수)을 결함 서명 2개만으로 계수단위 완전복원**했고(2회 재현), 그 성립 조건(인과대조 빌드 + 고정 nonce)이 정직하게 공개되어 있다. **"레퍼런스를 물리로 깼다"가 아니라 "깨끗한 스킵을 허용하는 구현은 물리적으로 완전히 뚫린다 + 레퍼런스의 저항은 우연이라 취약하다"**는 실현성/동기부여 결과로 위치시키면 후속 논문으로 유효하다.

---

## 1. 무엇을 했나 (개요)

- **공격**: T1 = c·s 곱셈을 클럭글리치로 스킵 → 결함 응답 `z_fault ≈ y1`(nonce). 깨끗한 서명 `z_clean = y1 + (-1)^b·LN·c·s1`과의 **2-trace 차분** `z_clean − z_fault = (-1)^b·LN·c·s1` → 공개 챌린지 `c`로 NTT 역산 → s1.
- **핵심 메커니즘**: c·s1은 비밀 다항식 3개(s1[0..2])를 **3-반복 루프**로 계산(반복당 ~50k 사이클, 전체 WIN≈192k). 글리치 지연(ext)이 어느 반복을 교란할지 결정하며, 스킵된 블록은 `T1_CS_ZEROINIT`로 사전 0화돼 있어 차분에 **그 블록만 깨끗한 `LN·c·s1[j]`**로 드러난다. 블록별로 모아 768/768.
- **장비**: STM32F405 + CW308 + ChipWhisperer-Husky, HSE 직결 7.37 MHz(adc_mul=1, PSS=4592).
- **빌드**: `haetae-JIG-T1-fused` (`VARIANT=baseline AXISA_JIG=1 T1_CS_ZEROINIT=1`). fast-jig(`J` prime/fire_t1)로 샷당 ~ms 스윕.

## 2. 결과 (정확 수치)

### 2.1 4단계 체인 (요약)
| 단계 | 내용 | 결과 |
|---|---|---|
| 1 | 복원체인 검증(글리치 없음, SW T1 모델 FL_CS) | s1 **768/768** (레퍼런스 산술과 비트일치) |
| 2 | 미수정 baseline 물리 글리치 | **누설 0 = 저항**(정상 결과) |
| 3 | jig 물리 클린 스킵 | 단일 블록 부분복원(~33%) |
| 4 | 다중결함 누적 | **s1 768/768 완전복원** |

### 2.2 완전복원 재현 (2회 독립 성공)
| 런 | 결함서명(최소) | 블록별 | 종료 샷수 | 클래스 분포 |
|---|---|---|---|---|
| 2026-07-18 (`t1_FULL_recovery_768.json`) | ext=41,421 → s1[0]; ext=91,670 → s1[1]+s1[2] | [256,256,256] | 108 | golden 62 / other 23 / mute 23 |
| 2026-07-19 (`t1_accum.csv`) | ext=41,421(w62,o13) → s1[0]; **ext=91,672(w67,o14) → s1[1]+s1[2]** | [256,256,256] | 594 | golden 351 / other 116 / mute 127 |

- 두 런 모두 **결함 서명 2개**로 768/768: 하나는 s1[0], 다른 하나는 **단일 글리치가 s1[1]·s1[2]를 동시 스킵**(loop-abort).
- 글리치 파라미터(공통): **width 55–68, offset 12–14, repeat 2** (Husky clock_xor, ext_single).
- 종료 샷수 차이(108 vs 594)는 파라미터 랜덤샘플링의 분산일 뿐 — 두 번 모두 성공.

### 2.3 대역·메커니즘 (2026-07-19 CSV 직접 증거)
| ext 대역 | 관측 block_match | rate | 해석 |
|---|---|---|---|
| ~41,420–41,460 | `[256, 0, 0]` | 0.333 | iter1만 스킵 → s1[0] 단일 |
| ~91,690–91,760 | `[1, 256, 0]` | 0.335 | iter2만 스킵 → s1[1] 단일 |
| **~91,672** | **`[0, 256, 256]`** | **0.667** | **iter1 후 loop-abort → s1[1]+s1[2] 동시** |
| ~142,110–142,730 | `[1, 0, ~250]` | ~0.29–0.33 | iter3 스킵 → s1[2] 단일 |

→ **ext가 c·s 루프의 어느 반복을 때리는지에 따라 단일 블록 스킵 또는 loop-abort(다중 블록)**가 발생. 대역 간격 ~50k는 반복당 사이클과 일치. (반복↔블록 경계의 명령어 수준 규명은 부록용 선택 과제.)

### 2.4 복원식·판정
- `ŝ1^(j)[k] = NTT(z̃^(j))[k] · ĉ[k]⁻¹ mod q`, `z̃ = diff/LN` (LN=8192).
- **무결성 게이트** `diff % LN == 0`(y1 완전상쇄 확인) 미충족 시 'other'(폐기).
- **판정** = 디바이스 참 s1('s' 스트림)과 NTT도메인 768 + 블록별 + 계수도메인 {-1,0,1}(=Montgomery {-14321,0,14321}) 정확일치. self-test로 복원 파이프라인 비트정확 검증.

## 3. 리뷰 — 강점

1. **엔드투엔드 물리 실증**: 시뮬/에뮬이 아닌 실HW 클럭글리치로 비밀 다항식 전체를 복원. 격자 서명에서 드문 완전복원 사례.
2. **재현성**: 서로 다른 날짜/파라미터에서 2회 독립 성공. 승리 파라미터(width·offset·repeat) 일관.
3. **정직성 내장**: 성립 3조건(인과대조 빌드·고정 nonce·참키 대조)이 코드·문서에 명시. 미수정 레퍼런스 저항도 함께 보고(단계 2).
4. **판정 엄밀성**: 검증실패가 아닌 **참키 계수단위 일치**로 성공 판정 + `diff%LN` 게이트로 쓰레기 배제 + self-test.
5. **메커니즘 규명**: loop-abort로 인한 단일/다중 블록 스킵을 CSV 증거로 설명 → "누적 공격"의 물리적 근거 제시.

## 5. 후속 논문 프레이밍 (권장 — 앞서 설명한 논리와 일관)

**논리적 취약성 ≠ 물리적 실현**을 축으로 서술:

1. **위치**: "HAETAE 응답 계산의 물리 오류주입 **실현성 연구**". 헤드라인 공격은 조건이 안 붙는 SW T2(현재 논문). 물리 T1은 **실현성 + IRV 동기부여**.
2. **핵심 주장(정직 버전)**: 
   - (a) c·s의 **clean 스킵이 물리적으로 실현 가능**하며(단일/다중 블록), 누적하면 **결함서명 2개로 s1 완전복원**.
   - (b) **미수정 융합 레퍼런스는 이 공격에 저항**하나, 그 저항은 *설계된 대응이 아니라* 융합 산술 + 버퍼 미초기화에 기댄 **우연**이라 컴파일러/최적화/코딩스타일로 소멸 가능.
   - (c) 따라서 **명시적 응답 무결성 보호(IRV)** 가 필요 — 우연적 저항에 의존할 수 없다.
3. **조건 공개**(반드시 본문 앞): 인과대조 빌드(disclosed, T2 twopass 대조와 동형)·고정 nonce(결정론 모드)·참키 대조(랩 검증 편의, W2로 보완).
4. **T2와의 관계**: T2(+y 스킵)는 물리적으로 융합 레퍼런스에서 clean 실현이 어려움(07-05, 누설 0). **T1은 c·s를 표적으로 2-trace 차분을 써서 물리 완전복원을 달성** — 즉 T1이 물리 실현성의 "성공 경로".

## 9. 총평

물리 T1 완전복원은 **실험적으로 견고하고(2회 재현) 정직하게 문서화**되어 있어, **"실현성 연구 + IRV 동기부여"로 프레이밍하면 후속 논문으로 충분**하다. 게재 안정성을 위해 **W2(공개키 독립검증)와 W3(full-sign 경로 교차검증) 두 실험만 추가**하면 방법론적 반박 여지가 사실상 사라진다. 절대 피해야 할 것은 이 결과를 "미수정 레퍼런스 격파"로 과대 서술하는 것 — 정직한 실현성 프레이밍이 더 강하고 안전하다.
