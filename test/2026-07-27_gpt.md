## 0. 문서의 핵심 결론

본 연구의 목표는 2013 RSA 논문의 모듈러스 확장이나 지수 분해를 HAETAE에 문자 그대로 이식하는 것이 아니다.

목표는 다음과 같다.

> **HAETAE의 전체 `c·s` 연산을 두 번 수행하지 않고, 원래의 `c·s` 연산을 한 번만 수행하면서 오류주입을 검출하고 최종 서명 출력을 감염시키는 대응기법을 구현한다.**

여기서 **“1회 연산”**은 다음처럼 정의한다.

- 허용하지 않음
  - HAETAE 서명 전체를 두 번 수행
  - `c·s`의 `NTT -> pointwise multiplication -> inverse NTT` 전체 경로를 재계산
  - 정상 결과와 재계산 결과를 비교한 뒤 `abort`하는 구조
- 허용함
  - 주 연산보다 훨씬 가벼운 독립 fingerprint 또는 태그 계산
  - 메시지·시도별 비밀 난수 태그 생성
  - 정상 시 상쇄되는 두 PRF/XOF 마스크
  - 노름 또는 제어 상태에 대한 경량 잔차 계산
  - 원본 키의 별도 읽기·언팩 또는 coefficient-domain 사본 보존

현재 분석 결과, 이 목표는 **구조적으로 가능하다**.

단, 다음과 같이 범위를 정확하게 구분해야 한다.

1. **독립 중복정보 없이 동일한 `z=y+c·s` 경로만으로 오류를 자동 감염시키는 방식**은 T1/T2 같은 term-drop 오류에 취약하다.
2. **오염된 `z`를 직접 큰 난수로 만든 뒤 정상 HAETAE 서명으로 방출하는 방식**은 rejection과 인코딩 구조에 맞지 않는다.
3. **원래 `c·s`는 한 번만 계산하고, 별도의 경량 독립 태그로 기대값과 관측값을 구성한 뒤, 두 감염 스트림을 정상 시 상쇄시키는 방식**은 적용 가능하다.

따라서 “HAETAE에서는 1회 연산 감염형 대응이 불가능하다”는 결론은 과도하다. 정확한 결론은 다음이다.

> **순수한 동일 데이터경로 내재형 감염은 어렵지만, 한 번의 full-cost `c·s` 연산과 독립적인 경량 fingerprint를 결합한 tag-cancellation 감염형 대응은 가능하다.**

# 1. 위협모델

## 1.1 사용자가 확정한 조건

본 분석에서는 다음을 전제로 한다.

- 개인키 `sk`, `s1`, `s2` 등 키정보는 보호 대상 연산에 입력되기 전에는 정상이다.
- 공격 대상은 연산 수행 중의 일시적 오류주입이다.
- 키 저장장치가 서명 시작 전부터 영구적으로 변조된 경우는 본 분석에서 제외한다.
- 공격자는 클럭·전압·전자기 글리치 등으로 다음 효과를 유발할 수 있다.
  - 명령 또는 루프 반복 스킵
  - 레지스터·메모리 중간값 bit flip
  - zeroing 또는 상수화
  - loop abort
  - 조건 분기 스킵
- 기본 분석은 한 번의 실행에서 하나의 일시적 오류가 발생하는 **single-fault model**이다.

## 1.2 보호 구간의 입력

`c·s` 세부연산을 분석할 때는 다음 값이 해당 보호 구간에 들어오는 시점에 정상이라고 본다.

\[
c,\quad s_1,\quad s_2,\quad b
\]

다만 전체 서명경로까지 보호하려면 다음도 별도 대응이 필요하다.

- `unpack_sk` 오류
- `c` 생성 경로의 오류
- `y` 샘플링 오류
- rejection 조건 계산 오류
- 서명 패킹·감염 적용 자체에 대한 오류

본 문서의 주 설계는 먼저 **`c·s` 세부연산을 한 번의 전체 계산으로 보호하는 방법**을 중심으로 한다.

## 1.3 2차 오류에 관한 한정

제안 구조는 `if (fault) abort` 분기를 두지 않으므로 다음 2차 오류에는 강하다.

- 1차 오류: `c·s` 또는 `+y` 오염
- 2차 오류: “오류 검출 후 중단” 분기 스킵

그러나 다음은 별도의 강화가 필요하다.

- 기대 태그와 관측 태그를 동시에 같은 방식으로 오염시키는 공통모드 다중 오류
- 두 감염 마스크 적용을 모두 스킵
- 감염 적용 직후 출력 버퍼를 정상값으로 복원
- 비밀 태그 난수 `rho`와 주 연산을 동시에 조작

따라서 논문에서는 “모든 다중오류에 안전”이 아니라 다음처럼 주장해야 한다.

> **탐지-후-중단 분기 스킵형 2차 오류에 내성이 있으며, 감염 적용 및 태그 경로 자체에 대한 동시 다중오류는 잔존 한계이다.**

# 2. 2013 RSA 논문에서 계승할 핵심

## 2.1 문자 그대로 이식하지 않는 요소

2013 RSA 논문은 다음을 사용한다.

- 작은 소수 \(r\)
- 확장 모듈러스 \(N'=N\cdot r\)
- 비밀 지수 분해
- 두 지수승 결과의 재결합
- \(m\bmod r\)와 \(c_1\bmod r\)로부터 만든 두 마스크의 XOR 상쇄

HAETAE에는 RSA의 다음 요소를 그대로 적용할 필요가 없다.

- \(N'=N\cdot r\) 방식의 모듈러스 확장
- RSA 지수 분해
- 페르마 소정리 자체
- 반복된 작은 잉여값을 그대로 XOR하는 마스크

## 2.2 계승할 철학

계승할 핵심은 다음 네 가지이다.

1. **전체 주 연산을 그대로 두고 저비용 보조 채널을 추가한다.**
2. **입력에서 계산한 기대 태그와 실제 결과에서 계산한 관측 태그를 사용한다.**
3. **정상 시 두 태그로 만든 감염값이 상쇄된다.**
4. **오류 시 상쇄가 깨져 최종 출력이 공격자에게 유용하지 않게 된다.**

2013 논문의 Algorithm 1은 정상 시 \(T_1=T_2\)이므로

\[
S\oplus T_1\oplus T_2=S
\]

가 되고, 오류 시 두 태그가 달라져 출력이 오염되는 구조이다.

HAETAE에서도 동일한 논리를 다음처럼 사용할 수 있다.

\[
\sigma^\star
=
\sigma
\oplus
\operatorname{PRF}_{K_I}(\Theta_E)
\oplus
\operatorname{PRF}_{K_I}(\Theta_O)
\]

정상 시

\[
\Theta_E=\Theta_O
\]

이므로 두 PRF 출력이 상쇄된다.

오류 시

\[
\Theta_E\neq\Theta_O
\]

가 되어 서명 바이트가 감염된다.

핵심은 **RSA의 수학구조를 복사하는 것이 아니라, “한 번의 주 연산 + 저비용 독립 태그 + 정상 상쇄”라는 설계 원칙을 HAETAE에 맞게 재구성하는 것**이다.

# 3. HAETAE 공식 원본 코드의 `c·s` 경로

분석 기준 소스:

- `docs/haetae_reference/src/sign.c`
- `docs/haetae_reference/src/poly.c`
- `docs/haetae_reference/src/ntt.c`
- `docs/haetae_reference/src/polyfix.c`
- `docs/haetae_reference/src/polyvec.c`
- `docs/haetae_reference/src/reduce.c`
- `docs/haetae_reference/include/params.h`

## 3.1 주요 파라미터: HAETAE-120 / MODE2

\[
N=256,\qquad q=64513,\qquad L=4,\qquad M=L-1=3,\qquad K=2
\]

\[
\eta=1,\qquad L_N=8192=2^{13},\qquad \tau=58
\]

비밀키 \(s_1\)은 세 개의 다항식으로 구성된다.

\[
s_1=(s_{1,0},s_{1,1},s_{1,2})
\]

각 다항식은 256개 계수를 가지므로 전체 비밀계수는 768개이다.

MODE2 원본 `poly_challenge()`에서 \(c\)는 \(\tau=58\)개의 계수가 1이고 나머지가 0인 sparse binary polynomial이다. 전역 부호는 이후 `b`에 따라 `polyvecl_cneg()`에서 적용된다.

## 3.2 서명 함수의 실제 순서

원본 `crypto_sign_signature_internal()`은 다음 순서로 동작한다.

### 1) 키 언팩과 NTT

```c
unpack_sk(A1, &s1, &s2, key, sk);

polyvecm_ntt(&s1);
polyveck_ntt(&s2);
```

`polyvecm_ntt(&s1)` 이후 `s1`은 coefficient domain이 아니라 NTT domain으로 변환된다.

### 2) `y` 샘플링과 `c` 계산

```c
counter = polyfixveclk_sample_hyperball(&y1, &y2, &b,
                                        seedbuf, counter);

...
poly_challenge(&c, buf, mu);
```

### 3) `c·s` 연산

```c
cs1.vec[0] = c;
chat = c;
poly_ntt(&chat);

for (i = 1; i < HAETAE_L; ++i) {
    poly_pointwise_montgomery(&cs1.vec[i],
                              &chat,
                              &s1.vec[i - 1]);
    poly_invntt_tomont(&cs1.vec[i]);
}

polyveck_poly_pointwise_montgomery(&cs2, &s2, &chat);
polyveck_invntt_tomont(&cs2);
```

즉 각 비밀 다항식에 대해

\[
c
\xrightarrow{\mathrm{NTT}}
\hat c
\]

\[
\hat c\circ\hat s_{1,i}
\xrightarrow{\mathrm{Montgomery\ reduction}}
\widehat{c s_{1,i}}
\]

\[
\widehat{c s_{1,i}}
\xrightarrow{\mathrm{InvNTT}}
c s_{1,i}
\]

가 수행된다.

### 4) 전역 부호

```c
polyvecl_cneg(&cs1, b & 1);
polyveck_cneg(&cs2, b & 1);
```

따라서 실제 응답 항은

\[
(-1)^b c s
\]

이다.

### 5) `+y`

```c
polyfixvecl_add(&z1, &y1, &cs1);
polyfixveck_add(&z2, &y2, &cs2);
```

`polyfix_add()`의 실제 연산은 다음과 같다.

```c
z[i] = y[i] + HAETAE_LN * cs[i];
```

즉 정수 고정소수점 영역에서

\[
z=y+L_N(-1)^b c s
\]

가 계산되며, 이 단계에는 모듈러 감산이 없다.

### 6) rejection

원본은 \(B_1\), \(B_0\) 경계를 계산해 `goto reject`를 수행한다.

# 4. 기존 “불가능” 판단에서 맞는 부분과 수정할 부분

## 4.1 맞는 부분: 동일 선형경로의 redundancy는 term-drop에 약하다

\[
z=y+u,\qquad u=L_N(-1)^b c s_1
\]

라고 하자.

동일한 선형 데이터 경로에서 값과 redundancy가 함께 계산된다면, \(u\) 전체가 스킵될 때 값뿐 아니라 그 항의 redundancy도 함께 사라질 수 있다.

예를 들어 선형 부호 \(C(\cdot)\)가

\[
C(z)=C(y)+C(u)
\]

를 만족하더라도 T1에서 \(u\)가 통째로 제거되면 결과 \(C(y)\)는 여전히 유효한 코드워드이다.

T2에서 \(y\)가 통째로 제거되면 \(C(u)\)도 유효한 코드워드이다.

따라서 다음 방식은 충분하지 않다.

> 주 연산의 각 데이터에 동일한 선형 중복정보를 붙여 같은 명령·같은 제어경로로 함께 이동시키는 방식

## 4.2 맞는 부분: NTT 좌표 하나만 검사하면 국소 오류를 놓친다

`poly_pointwise_montgomery()`는 NTT 좌표 256개를 독립적으로 곱한다.

NTT 좌표 \(j=91\)에만 오류가 발생했는데 \(j=13\)만 검사하면 검사 좌표는 변하지 않는다.

Python 원본산술 재현에서도 다음이 확인되었다.

```text
checked_root                 = 13
faulted_ntt_coordinate       = 91
checked_coordinate_changed   = False
faulted_coordinate_changed   = True
```

따라서 단일 NTT 평가점, 단일 고정 좌표 또는 공개된 소수 좌표만 검사하는 것은 공격자가 미검사 위치를 선택할 수 있는 표적 오류모델에 충분하지 않다.

## 4.3 맞는 부분: `z` 자체를 큰 난수로 만들면 HAETAE 구조와 충돌한다

HAETAE 서명은 짧은 응답과 rejection·압축 인코딩을 요구한다.

`z`를 직접 균일난수처럼 오염시키면 다음이 발생한다.

- \(B_0/B_1\) 노름 위반
- 인코딩 실패
- rejection loop 재진입
- 비정상 범위 계수

따라서 감염은 `z` 내부가 아니라 **서명이 정상적으로 패킹된 이후의 직렬화 바이트**에 적용하는 것이 적절하다.

## 4.4 수정할 부분

앞의 사실들은 다음을 증명하지 않는다.

> HAETAE에서 전체 `c·s`를 한 번만 계산하는 감염형 대응은 불가능하다.

실제로 필요한 것은 주 연산과 독립적인 경량 태그 경로이다.

따라서 수정된 결론은 다음이다.

> **동일 데이터경로만 이용하는 순수 내재형은 어렵지만, 한 번의 원본 `c·s`와 독립적인 random linear fingerprint를 결합하면 정상 태그 상쇄형 감염 대응을 구성할 수 있다.**

# 5. 제안 구조: 단일 전체연산 태그-상쇄 감염형 대응

이 문서에서는 임시 명칭으로 다음을 사용한다.

> **SFO-TC: Single-Full-Operation Tag-Cancellation**

명칭은 잠정적이며, 핵심은 다음 구조이다.

\[
\boxed{
\text{원본 }c\cdot s\text{ 전체 계산 1회}
+
\text{독립 경량 fingerprint}
+
\text{정상 시 두 감염 스트림 상쇄}
}
\]

# 6. `c·s` 보호용 random linear fingerprint

## 6.1 수학적 정의

환을 다음과 같이 둔다.

\[
\mathcal R_q=\mathbb F_q[x]/(x^{256}+1)
\]

\(c\)에 의한 negacyclic convolution 행렬을 \(C_c\)라 하면

\[
u_i=c s_{1,i}=C_c s_{1,i}
\]

이다.

비밀·신선한 난수 벡터를 생성한다.

\[
\rho_i
\leftarrow
\operatorname{XOF}
(K_\rho\parallel\mu\parallel\text{attempt}\parallel i)
\in\mathbb F_q^{256}
\]

여기서:

- \(K_\rho\): 서명용 비밀키에서 도메인 분리해 만든 태그 키
- \(\mu\): 메시지 해시
- `attempt`: rejection 시도 번호
- \(i\): 비밀 다항식 블록 번호

## 6.2 기대 태그

주 NTT 경로와 독립적으로 다음을 계산한다.

\[
\boxed{
\tau_{E,i}
=
(-1)^b
(C_c^T\rho_i)^T s_{1,i}
\pmod q
}
\]

중요한 조건:

- coefficient-domain \(c\) 사용
- coefficient-domain \(s_{1,i}\) 사용
- 주 연산의 `chat`, NTT-domain `s1`, `cs1` 사용 금지
- 별도 shift-add 또는 sparse convolution 코드 사용

## 6.3 관측 태그

원본 코드가 실제 생성한 `cs1.vec[i+1]`에 `cneg`까지 적용한 뒤 다음을 계산한다.

\[
\boxed{
\tau_{O,i}
=
\rho_i^T\widetilde{u}_i
\pmod q
}
\]

정상 실행이면

\[
\widetilde{u}_i=(-1)^b C_c s_{1,i}
\]

이므로

\[
\tau_{O,i}
=
\rho_i^T(-1)^bC_c s_{1,i}
=
(-1)^b(C_c^T\rho_i)^Ts_{1,i}
=
\tau_{E,i}.
\]

## 6.4 오류가 발생한 경우

오류 결과를

\[
\widetilde{u}_i=u_i+e_i
\]

라고 하면

\[
\tau_{O,i}-\tau_{E,i}
=
\rho_i^T e_i.
\]

\(e_i\neq0\)이고 \(\rho_i\)가 공격자가 예측하지 못하는 균일 벡터라면

\[
\Pr[\rho_i^T e_i=0]=\frac1q.
\]

HAETAE의 \(q=64513\)이므로 한 태그의 이론적 충돌확률은

\[
\frac1{64513}
\approx1.55\times10^{-5}.
\]

독립 태그 두 개를 사용하면

\[
\frac1{64513^2}
\approx2.40\times10^{-10}.
\]

이는 결정론적 완전 재계산은 아니며 확률적 검출이다. 대신 full NTT 곱셈 재계산을 피한다.

---

# 7. 왜 이 방식은 `c·s` 전체 재계산이 아닌가

기대 태그 계산은 \(c s_{1,i}\) 전체 다항식을 만들지 않는다.

먼저

\[
a_i=C_c^T\rho_i
\]

를 계산하고,

\[
\tau_{E,i}=a_i^T s_{1,i}
\]

라는 하나의 스칼라만 계산한다.

MODE2의 \(c\)는 weight 58의 binary sparse polynomial이므로 \(C_c^T\rho_i\)는 58개의 negacyclic shift를 더하거나 빼는 방식으로 계산할 수 있다.

공통 \(\rho\)를 쓰는 설계에서는 대략 다음 연산이 필요하다.

- \(C_c^T\rho\): \(58\times256=14,848\) add/sub
- 세 \(s_1\) 블록 기대 태그: \(3\times256=768\) signed add
- 세 관측 태그: \(3\times256=768\) multiply-accumulate

반면 full recomputation은 다음을 다시 수행한다.

- `poly_ntt(c)`
- 세 번의 pointwise multiplication
- 세 번의 inverse NTT

따라서 random linear fingerprint는 **전체 결과 다항식을 두 번째로 계산하지 않고 스칼라 무결성 정보를 계산하는 것**이다.

정확한 cycle overhead는 C 구현 후 STM32F4에서 실측해야 하며, 위 수치는 연산량 분석일 뿐 실측치가 아니다.

# 8. 정상 상쇄형 감염 출력

## 8.1 태그 transcript

기대 태그들을 직렬화한다.

\[
\Theta_E
=
\operatorname{enc}
(\tau_{E,0},\tau_{E,1},\tau_{E,2},\ldots)
\]

관측 태그들을 직렬화한다.

\[
\Theta_O
=
\operatorname{enc}
(\tau_{O,0},\tau_{O,1},\tau_{O,2},\ldots)
\]

다음 context를 반드시 포함한다.

- 도메인 분리 문자열
- \(\mu\)
- rejection 시도 번호
- 파라미터 모드
- 필요 시 \(c\), \(b\)의 해시
- 태그 종류와 블록 번호

## 8.2 두 감염 스트림

\[
M_E
=
\operatorname{SHAKE256}
(K_I\parallel\text{ctx}\parallel\Theta_E)
\]

\[
M_O
=
\operatorname{SHAKE256}
(K_I\parallel\text{ctx}\parallel\Theta_O)
\]

## 8.3 최종 출력

정상 서명 \(\sigma\)를 먼저 패킹한 뒤 다음을 적용한다.

\[
\boxed{
\sigma^\star
=
\sigma\oplus M_E\oplus M_O
}
\]

### 정상 실행

\[
\Theta_E=\Theta_O
\Rightarrow
M_E=M_O
\]

이므로

\[
\sigma^\star=\sigma.
\]

### 오류 실행

\[
\Theta_E\neq\Theta_O
\]

이면 PRF/XOF 가정하에서 두 스트림은 독립적으로 보이므로

\[
M_E\oplus M_O
\]

가 서명 바이트를 예측 불가능하게 오염시킨다.

## 8.4 이 구조의 장점

다음 코드가 필요 없다.

```c
if (tau_expected != tau_observed)
    abort();
```

다음 코드도 필요 없다.

```c
if (delta)
    infect();
```

즉:

- 명시적 equality 비교 없음
- 오류 검출 후 중단 분기 없음
- 1비트 `delta` 없음
- 정상 시 태그 흔적이 출력에서 완전히 소거
- 오류 시 패킹된 서명 전체 또는 누설 관련 필드가 감염

## 9.1 coefficient-domain 비밀키 확보

원본은 `s1`을 서명 루프 전에 제자리 NTT 변환한다.


따라서 기대 태그를 위해 다음 중 하나가 필요하다.

### 방법 A: 사본 보존

```c
polyvecm s1_plain, s1_ntt;
```

- 구현 단순

단점:

- MODE2 기준 약 3 KiB 추가 RAM

### 방법 B: packed `sk`에서 태그용 `s1`을 별도 언팩

- 주 경로는 기존 `s1` 사용
- 기대 태그 계산 시 packed secret key에서 독립적으로 재언팩
- 가능하면 태그 dot product를 packed ternary 형식에서 직접 계산

장점:

- 공통모드 오류 감소
- 추가 RAM 최적화 가능

단점:

- 별도 언팩 코드 필요
- 패킹 형식에 종속

위협모델상 `sk`는 함수 입력 시 정상이다. 그러나 `unpack_sk` 중 오류도 보호하려면 **주 경로와 태그 경로가 같은 mutable `s1` 객체를 공유하지 않아야 한다.**

# 11. T2 `+y` 보호 확장

원본은 정확히 다음을 계산한다.

\[
z=y+L_Nu,\qquad u=(-1)^bcs
\]

별도의 비밀 벡터 \(\rho_z\)와 태그 모듈러스 \(p_z\)를 사용한다.

## 11.1 기대 태그

\[
\zeta_E
=
\rho_z^Ty
+
L_N\rho_z^Tu
\pmod {p_z}
\]

## 11.2 관측 태그

\[
\zeta_O
=
\rho_z^Tz
\pmod {p_z}
\]

정상 시

\[
\zeta_E=\zeta_O.
\]

T2에서 `+y`가 스킵되면

\[
z=L_Nu
\]

이므로

\[
\zeta_O-\zeta_E=-\rho_z^Ty.
\]

따라서 높은 확률로 mismatch가 발생한다.

## 11.3 태그 모듈러스 선택

`z`는 모듈러 \(q\) 원소가 아니라 고정소수점 정수이다. 따라서 다음 선택을 검토해야 한다.

1. \(q\)로 reduction
   - 구현 단순
   - 정수 차이가 \(q\)의 배수인 오류를 놓칠 수 있음
2. 별도 32비트 소수 \(p_z\)
   - `z` 관계를 독립적으로 보호
   - 64비트 누산·감산 비용 필요
3. 독립된 두 작은 소수
   - 충돌 확률 감소
   - 연산량 증가
4. 64비트 wraparound fingerprint
   - 빠를 수 있음
   - 충돌확률 증명을 별도로 해야 함

현재 단계에서는 **`c·s`는 mod-\(q\) fingerprint, `z` 정수관계는 별도 소수 \(p_z\) fingerprint**가 가장 명확한 설계이다.

# 12. rejection 우회 보호 확장

원본은 `reject1`, `reject2`를 계산한 뒤 정상 알고리즘의 `goto reject`를 수행한다.

정상 출력의 기대 상태는 다음이다.

\[
r_E=(0,0)
\]

관측 상태는 다음이다.

\[
r_O=(reject1,reject2)
\]

따라서 transcript를 다음처럼 확장할 수 있다.

\[
\Theta_E=
(\tau_E,\zeta_E,0,0)
\]

\[
\Theta_O=
(\tau_O,\zeta_O,reject1,reject2)
\]

정상 실행에서는 출력 단계에 도달했을 때 두 reject bit가 0이다.

공격으로 `goto reject` 분기만 스킵되면 reject bit는 1인 상태로 남으므로 두 마스크가 상쇄되지 않는다.

주의:

- rejection **분기 스킵**은 위 방식으로 막을 수 있다.
- reject bit의 **계산 자체를 zeroing**하는 오류는 기존 bit만 transcript에 넣어서는 잡히지 않는다.
- 이 경우에는 별도의 경량 노름 재계산 또는 독립 residual이 필요하다.

노름 재검사는 `c·s` 전체 재계산이 아니므로 “원본 `c·s` 한 번”이라는 목표와 양립한다.

# 15. 제안 의사코드

```text
Input:
    정상 packed secret key sk
    message M
    randomness rnd

Output:
    signature sigma*

1.  sk에서 주 연산용 s1_main과 태그용 s1_tag를 독립적으로 준비
2.  s1_main을 NTT domain으로 변환
3.  reject loop:
4.      y, b 샘플링
5.      c 계산
6.      rho_cs, rho_z를 secret key, mu, attempt에서 파생
7.      tauE_cs <- coefficient-domain c와 s1_tag로 기대 c*s fingerprint 계산
8.      원본 HAETAE c*s 연산을 정확히 한 번 수행
9.      (-1)^b 부호 적용
10.     tauO_cs <- 실제 cs 결과의 관측 fingerprint
11.     z <- y + LN*cs
12.     zetaE <- y, cs로 기대 z 관계 fingerprint
13.     zetaO <- 실제 z의 관측 fingerprint
14.     reject1, reject2 계산
15.     정상 알고리즘대로 reject 여부 처리
16.     hint와 sigma 패킹
17.     ThetaE <- tauE_cs || zetaE || 0 || 0 || context
18.     ThetaO <- tauO_cs || zetaO || reject1 || reject2 || context
19.     ME <- PRF_KI(ThetaE), 서명 길이로 확장
20.     MO <- PRF_KI(ThetaO), 서명 길이로 확장
21.     sigma* <- sigma XOR ME XOR MO
22.     return sigma*
```

# 16. 구현 시 반드시 지켜야 할 독립성

## 16.1 주 경로와 태그 경로의 입력 분리

다음은 사용하면 안 된다.

```c
tauE = tag(cs1);   // 주 연산 결과로 기대 태그까지 계산
tauO = tag(cs1);
```

항상 같으므로 오류를 검출할 수 없다.

다음도 위험하다.

```c
poly_ntt(&chat);
tauE = tag_from_chat(chat, s1_ntt);
main_cs = pointwise(chat, s1_ntt);
```

`chat` 또는 `s1_ntt`가 태그 계산 전에 오염되면 두 경로가 같은 잘못된 값을 사용할 수 있다.

권장 방식:

- 기대 태그: coefficient-domain `c`, 독립 `s1_tag`
- 주 연산: NTT-domain `chat`, `s1_main`
- 관측 태그: 실제 post-inverse-NTT `cs1`

## 16.2 비밀·신선한 \(\rho\)

\(\rho\)가 공개·고정이면 공격자가

\[
\rho^Te=0
\]

을 만족하는 오류를 선택할 수 있다.

따라서 다음을 권장한다.

\[
\rho
=
\operatorname{XOF}
(K_\rho\parallel\mu\parallel\text{attempt}\parallel\text{block})
\]

- 서명마다 변경
- rejection 시도마다 변경
- 블록마다 도메인 분리
- 외부 출력 금지

## 16.3 감염 마스크의 비밀키화

태그값을 그대로 반복 XOR하면 작은 태그 구조가 출력에 남는다.

반드시 keyed XOF/PRF로 전체 서명 길이에 확장한다.

```text
mask = SHAKE256(secret_key || context || tag)
```

## 16.4 비교분기 제거

다음 코드는 사용하지 않는다.

```c
if (tauE != tauO)
    delta = 1;
```

다음도 사용하지 않는다.

```c
if (delta)
    infect(sig);
```

두 태그를 독립적으로 PRF에 넣고 두 스트림을 항상 XOR한다.

# 17. 예상 보안 성질

## 17.1 정상성

무결함 실행에서

\[
\Theta_E=\Theta_O
\]

이므로

\[
\sigma^\star=\sigma.
\]

따라서 원본 HAETAE 서명과 bit-exact하게 일치해야 한다.

이 조건은 구현 검증에서 필수이다.

## 17.2 한 경로의 단일 오류

단일 오류가 주 연산 경로에만 영향을 주면:

\[
\Theta_E\neq\Theta_O
\]

가 높은 확률로 성립한다.

단일 오류가 태그 기대 경로에만 영향을 주어도 동일하게 mismatch가 발생한다.

단일 오류가 두 PRF 중 하나에 영향을 주어도 정상 상쇄가 깨지므로 출력은 감염된다.

## 17.3 미탐 확률

하나의 mod-\(q\) random linear fingerprint:

\[
P_{\text{miss}}\leq 1/q
\]

두 개의 독립 fingerprint:

\[
P_{\text{miss}}\leq 1/q^2
\]

단, 이 식은 다음 조건이 필요하다.

- 오류벡터가 \(\rho\) 선택 이후 \(\rho\)에 적응하지 못함
- \(\rho\)가 공격자에게 알려지지 않음
- 주 경로와 태그 경로가 동일한 single fault로 동시에 같은 오류를 받지 않음
- 오류가 태그 모듈러스에서 비영임

## 17.4 검출 후 분기 스킵

검출 후 중단 분기가 존재하지 않으므로 해당 분기를 스킵하는 방식은 성립하지 않는다.

이것이 기존 detect-and-abort 방식과 구분되는 핵심이다.

# 18. 현재 설계의 잔존 한계

## 18.1 확률적 검출

full recomputation과 달리 fingerprint는 충돌 가능성이 있다.

이를 줄이려면:

- 독립 태그 2개 사용
- `c·s` 태그와 `z` 태그를 서로 다른 modulus·seed로 분리
- 블록별 태그 유지
- 비밀·신선한 \(\rho\) 사용

## 18.2 공통모드 오류

주 경로와 기대 태그가 같은 mutable 입력이나 계산값을 공유하면 동일 오류가 두 경로에 전파될 수 있다.

해결:

- packed key에서 태그용 값을 독립적으로 읽기
- `c`와 `s1`의 주 경로·태그 경로 분리
- 코드·시간·레지스터 배치 분산
- 필요 시 태그 계산을 주 연산 전후로 분할

## 18.3 감염 적용 단일점

다음 코드 자체가 스킵되면 감염이 적용되지 않을 수 있다.

```c
sig[i] ^= maskE[i] ^ maskO[i];
```

이는 별도의 하드닝 대상이다.

가능한 보강:

- 감염 XOR을 두 구간으로 나누어 수행
- 서명 필드별 분산 감염
- 패킹 과정에 마스크를 직조
- 메모리 쓰기 순서를 분산
- 최종 출력 전 데이터 흐름에 마스크를 누적

단, 이를 모두 적용하더라도 “모든 다중오류 안전”으로 과장해서는 안 된다.

## 18.4 정상 rejection 분기

HAETAE 알고리즘 자체의 rejection loop는 제거할 수 없다.

제거 대상은 **오류 검출용 추가 abort 분기**이다.

## 18.5 부채널

비밀 \(\rho\), \(K_I\), fingerprint dot product는 새로운 부채널 누설 표면을 만들 수 있다.

따라서 추후 다음을 분석해야 한다.

- \(\rho\) 생성의 전력·EM 누설
- \(s_1\) coefficient-domain dot product
- 조건부 연산 여부
- 태그 모듈러 감산의 constant-time 구현

# 20. 논문에서 사용할 수 있는 주장과 피해야 할 주장

## 20.1 사용할 수 있는 주장

> HAETAE의 `c·s` 전체 NTT 곱셈을 재실행하지 않고, coefficient-domain 입력에서 계산한 독립 random linear fingerprint와 실제 NTT 결과의 fingerprint를 정상 시 상쇄되는 감염 스트림으로 결합할 수 있다.

> 제안 방식은 원본 `c·s` 연산을 한 번만 수행하며, 오류 검출 후 중단하는 제어분기를 사용하지 않는다.

> 단일 주 연산 경로 오류에 대해 mismatch 확률은 하나의 mod-\(q\) 태그에서 최대 \(1/q\), 두 독립 태그에서 최대 \(1/q^2\)로 제한된다.

> 감염은 HAETAE의 짧은 응답 `z` 내부가 아니라 패킹된 서명 바이트에 적용하므로 rejection·인코딩 구조와 충돌하지 않는다.

## 20.2 피해야 할 주장

> HAETAE에서 순수 감염형은 수학적으로 불가능하다.

현재 형식적 불가능성 증명이 없다.

> 모든 단일·다중 오류에 완전 안전하다.

태그 충돌, 공통모드 오류, 감염 적용 스킵이 남는다.

> 구현 오버헤드는 매우 작다.

C 및 STM32F4 실측 전에는 정량 주장 불가하다.

> 2013 RSA 방식을 그대로 HAETAE에 적용했다.

실제 계승 대상은 모듈러스 확장이 아니라 정상 상쇄형 감염 철학이다.

> 기존 IRV와 동일하게 결정론적 완전 검출이다.

random linear fingerprint는 확률적이다.

# 21. 현재 최종 판단

## 21.1 연구 질문

> HAETAE의 `c·s`를 두 번 계산하지 않고 한 번의 전체 연산만으로 오류주입공격에 대응할 수 있는가?

## 21.2 답

\[
\boxed{\text{가능하다.}}
\]

다만 “추가 연산이 전혀 없는 한 번의 명령경로”가 아니라 다음 구조이다.

\[
\boxed{
\text{원본 full }c\cdot s\text{ 1회}
+
\text{경량 독립 fingerprint}
+
\text{정상 태그 상쇄형 출력 감염}
}
\]

## 21.3 가장 유력한 설계

1. coefficient-domain \(c,s_1\)에서 기대 random linear fingerprint 계산
2. 원본 NTT 기반 `c·s`는 정확히 한 번 수행
3. 실제 `cs1`에서 관측 fingerprint 계산
4. 필요 시 `z=y+L_Ncs` 관계 태그 추가
5. rejection 상태 추가
6. 기대 transcript와 관측 transcript를 각각 keyed XOF에 입력
7. 두 XOF 스트림을 항상 서명에 XOR
8. 정상 시 상쇄, 오류 시 감염
9. detect-and-abort 비교분기 없음

## 21.4 기존 Claude 분석의 최종 재평가

Claude 분석에서 타당한 부분:

- 동일 선형 경로 redundancy의 term-drop 투명성
- 단일 NTT 평가점의 국소성
- 큰 `z` 직접 감염과 rejection·인코딩의 충돌
- 감염 적용 및 residual 경로의 단일점 한계

수정해야 할 부분:

- 위 사실로부터 모든 single-full-operation 감염형 대응의 불가능성을 결론 내린 것
- 전체 `c·s` 재계산과 경량 독립 fingerprint를 동일하게 본 것
- `z` 내부 감염 실패를 패킹 후 tag-cancellation 감염 실패로 일반화한 것

최종적으로 다음 문장이 가장 정확하다.

> **HAETAE의 아핀 응답식 안에서 독립 중복성 없이 오류를 자동 확산시키는 순수 내재형은 어렵다. 그러나 원본 `c·s`를 한 번만 수행하고, 독립 random linear fingerprint와 정상 상쇄형 두 감염 스트림을 사용하면, full recomputation 없이 T1 계열의 NTT·pointwise·inverse NTT·loop·부호 오류를 보호할 수 있다. T2와 RB도 별도 관계 태그와 상태 잔차를 같은 transcript에 추가해 통합할 수 있다.**

0. 요약 결론

본 연구의 목적은 2013년 RSA 논문의 모듈러스 확장, 지수 분해, 페르마 정리를 HAETAE에 그대로 이식하는 것이 아니다.

목표는 다음과 같다.

HAETAE의 고비용 전체 c·s 경로를 두 번 수행하지 않고 한 번만 수행하면서, 연산 중 오류주입으로 만들어진 결함 서명이 공격자에게 유용한 키정보를 방출하지 못하도록 검출·감염시키는 대응기법을 구현한다.

현재까지의 핵심 판정은 다음과 같다.

HAETAE 응답

$$z=y+(-1)^bL_N(c\cdot s)$$

내부에만 중복성을 넣어 오류가 자동 확산되도록 하는 순수 z-내재형 감염은 T1/T2와 같은 term-drop 오류에 구조적 한계가 있다.

그렇다고 해서 한 번의 전체 c·s 연산에 기반한 감염형 대응 전체가 불가능한 것은 아니다.

현재 가장 유력한 상위 구조는 다음이다.

$$\boxed{\text{원본 }c\cdot s\text{ 전체연산 1회}+\text{독립 무결성 transcript}+\text{post-encode 태그 상쇄 감염}}$$

반응 구조는 다음처럼 구성한다.

$$M_E=\operatorname{XOF}_{K_I}(\mathrm{ctx}\parallel\Theta_E)$$

$$M_O=\operatorname{XOF}_{K_I}(\mathrm{ctx}\parallel\Theta_O)$$

$$\boxed{\sigma^*=\sigma\oplus M_E\oplus M_O}$$

정상 실행에서는

$$\Theta_E=\Theta_O$$

이므로 두 감염 스트림이 상쇄되어 원래 서명이 보존된다.

오류 실행에서는 기대 transcript와 관측 transcript가 달라져 두 스트림이 상쇄되지 않고, 직렬화된 서명 출력이 감염된다.

이 구조의 가장 큰 연구 가치는 현재 IRV의 if 기반 잔차 생성과 delta -> factor 반응을 제거할 가능성이다.

다만 검출 방식별 판정은 구분해야 한다.

1. 연구 목표와 “1회 연산”의 의미

1.1 사용자가 확정한 연구 목표

본 연구가 구현하려는 것은 다음이다.

전체 c·s를 두 번 계산하는 대응이 아니라, 전체 c·s를 한 번만 계산하고 저비용 독립 무결성 정보와 감염 반응을 추가하는 대응기법

2013년 RSA 논문과 동일한 수학식을 HAETAE에 복사하려는 것이 아니다. 참고하는 것은 다음 설계 철학이다.

전체 고비용 연산을 단순 복제하지 않는다.

저비용 보조 관계를 계산한다.

정상 실행에서는 보조값이 상쇄되어 원래 출력이 보존된다.

오류 실행에서는 상쇄가 깨져 공격자가 유용한 결함 출력을 얻지 못한다.

오류 여부에 따른 if (fault) abort 분기를 두지 않는다.

1.2 “1회 연산”의 정확한 정의

본 문서에서 “1회 연산”은 단일 CPU 명령을 뜻하지 않는다. 다음과 같이 정의한다.

허용하지 않는 것

HAETAE 서명 전체를 두 번 수행

다음 c·s 전체 경로를 두 번 수행

$$\operatorname{NTT}(c)\rightarrow\text{pointwise Montgomery multiplication}\rightarrow\operatorname{InvNTT}$$

전체 재계산 결과를 실제 결과와 비교한 뒤 중단

허용하는 것

원래 c·s 전체 경로는 한 번만 수행

전체 c·s보다 낮은 비용의 독립 fingerprint 또는 부분 witness

이미 계산된 cs를 재사용한 +y 재덧셈

노름의 독립 재검사

기대·관측 transcript에서 생성한 두 감염 스트림의 정상 상쇄

따라서 연구 목표는 무중복(zero redundancy) 이 아니라 단일 전체연산(single full computation) 이다.

2.3 2차 오류에 대한 정확한 주장 범위

태그 상쇄형 반응은 if (fault) abort 분기가 없으므로 다음 유형에 강하다.

1차 오류: T1/T2/RB 등의 민감연산 오류

2차 오류: 대응기법의 “탐지 후 중단” 분기 스킵

그러나 다음까지 자동으로 해결하는 것은 아니다.

탐지-후-중단 분기 스킵형 2차 오류에 내성을 제공하며, 감염 적용과 transcript 생성 경로를 동시에 표적으로 하는 일반 다중오류는 잔존 한계이다.

3. 2013 RSA 논문에서 참조하는 원리

3.1 논문이 실제로 제안한 구조

업로드된 2013년 논문은 classical RSA에서 다음을 수행한다.

작은 소수 $r$ 생성

$N'=N\cdot r$ 구성

비밀지수 분해

두 지수승 수행

입력 잉여로 만든 $T_1$과 중간결과 잉여로 만든 $T_2$를 출력에 XOR

정상 실행에서는 페르마 정리에 의해

$$T_1=T_2$$

이므로

$$S^*=S\oplus T_1\oplus T_2=S$$

가 된다. 오류가 발생하면 두 태그가 달라져 출력 전체에 오염이 남는다.

논문은 비교 연산을 사용하지 않는 점과, 전체 고비용 연산을 단순히 두 번 복제하는 것보다 낮은 추가비용을 강조한다. 논문 5쪽의 표는 1024비트 모듈러스와 64비트 $r$의 예에서 약 18.79% 오버헤드를 제시한다.

3.2 HAETAE에 그대로 적용하지 않는 요소

다음은 HAETAE에 직접 복사할 대상이 아니다.

$N'=N\cdot r$ 모듈러스 확장

RSA 비밀지수 분해

페르마 소정리 자체

두 지수승 재결합

작은 잉여 패턴의 단순 반복 XOR

3.3 계승할 추상 구조

HAETAE에 계승할 핵심은 다음이다.

$$\text{정상관계}\Rightarrow\Theta_E=\Theta_O\RightarrowM_E=M_O\RightarrowM_E\oplus M_O=0$$

즉, 구체적인 RSA 산술이 아니라 다음 철학을 참조한다.

고비용 연산 전체를 중복하지 않음

기대값과 관측값을 독립 경로에서 구성

정상 시 자동 상쇄

오류 시 출력 감염

검출 후 중단 분기 제거

6. 기존 “불가능성” 분석의 정확한 범위

기존 분석은 다음 조건을 동시에 만족하는 순수 내재형 설계가 어렵다고 판단했다.

독립 태그·재검산이 없음

$z=y+(-1)^bL_Nc\cdot s$ 내부 연산만으로 결함이 자동 난수화됨

이 판단의 핵심은 타당하다.

6.1 선형 코드워드 문제

선형 태그 $C(\cdot)$를 값과 같은 경로로 함께 계산하면

$$C(z)=C(y)+C(c\cdot s)$$

이다.

T1으로 $c\cdot s$ 항 전체가 빠지면

$$z'=y,\qquad C(z')=C(y)$$

가 되어 여전히 정상 코드워드이다.

T2로 $y$ 항 전체가 빠져도

$$z'=c\cdot s,\qquad C(z')=C(c\cdot s)$$

이므로 같은 문제가 발생한다.

6.2 짧은 서명·인코딩 문제

오류를 $z$ 자체에서 큰 난수로 확산시키면 다음 문제가 생긴다.

$B_0/B_1$ 노름 게이트 실패

range encoding 실패

rejection loop 재진입

따라서 감염 반응은 $z$ 내부보다 서명 패킹 후 직렬화된 출력에 적용하는 것이 구조적으로 적합하다.

6.3 기존 분석에 대한 공정한 서술

다음 표현은 부정확하다.

기존 Claude 분석이 모든 single-full-operation 감염형을 불가능하다고 결론냈다.

보다 정확한 표현은 다음이다.

기존 분석은 독립 중복성이 없는 순수 z-내재형의 한계를 보였고 post-encode 감염과 경량 태그를 현실적인 방향으로 남겼다. 현재 설계는 그 방향을 기대·관측 transcript의 정상 상쇄 구조로 구체화한다.

즉, 현재 제안은 이전 판단을 뒤집는 것이 아니라 불가능성 논증이 남긴 실현 가능한 형태를 더 구체적이고 비교 없는 구조로 발전시킨 것이다.

7. 태그 상쇄 반응 구조

7.1 기본식

기대 transcript와 관측 transcript를 각각 구성한다.

$$\Theta_E=\operatorname{encode}(\text{expected integrity information})$$

$$\Theta_O=\operatorname{encode}(\text{observed integrity information})$$

두 감염 스트림은 동일한 keyed XOF로 생성한다.

$$M_E=\operatorname{XOF}_{K_I}(\mathrm{ctx}\parallel\Theta_E)$$

$$M_O=\operatorname{XOF}_{K_I}(\mathrm{ctx}\parallel\Theta_O)$$

최종 서명은 다음과 같다.

$$\boxed{\sigma^*=\sigma\oplus M_E\oplus M_O}$$

7.2 정상 실행

$$\Theta_E=\Theta_O$$

이면

$$M_E=M_O$$

이므로

$$\sigma^*=\sigma.$$

7.3 오류 실행

민감연산 오류로

$$\Theta_E\neq\Theta_O$$

가 되면 두 XOF 출력이 달라져 서명이 감염된다.

또한 두 XOF 호출, 상태, 출력 버퍼도 가능한 한 분리해야 한다. 이는 완전한 다중오류 내성을 증명하지는 않지만, 한 개의 제어흐름 오류가 두 경로를 동시에 제거하는 공통 단일점을 줄인다.

9. T1 검출 후보 2: 균일 random-linear fingerprint

9.1 정의

각 비밀 다항식에 대해

$$u_i=C_cs_i=c\cdot s_i$$

라고 하자. $C_c$는 $c$에 의한 negacyclic convolution 행렬이다.

메시지·비밀키·시도 번호에서 균일 비밀 벡터

$$\rho\in\mathbb F_q^{256}$$

를 생성한다.

기대 태그는 입력에서 계산한다.

$$\boxed{\tau_{E,i}=(C_c^T\rho)^Ts_i\pmod q}$$

관측 태그는 실제 원본 NTT 경로 결과에서 계산한다.

$$\boxed{\tau_{O,i}=\rho^T\widetilde u_i\pmod q}$$

정상 실행에서는

$$\tau_{E,i}=(C_c^T\rho)^Ts_i=\rho^TC_cs_i=\rho^Tu_i=\tau_{O,i}.$$

오류 결과가

$$\widetilde u_i=u_i+e_i$$

이면

$$\tau_{O,i}-\tau_{E,i}=\rho^Te_i.$$

$e_i\neq0$이고 $\rho$가 공격자에게 알려지지 않은 균일 벡터이면

$$\Pr[\rho^Te_i=0]=\frac1q.$$

HAETAE의 $q=64513$에서는 한 fingerprint의 이론적 미탐확률이 약

$$1.55\times10^{-5}$$

이다.

11. Claude가 제안한 NTT 근 평가점 태그의 재검증

11.1 제안식

Claude는

$$\alpha^{256}=-1\pmod q$$

인 비밀 평가점을 사용하여

$$\tau_E=c(\alpha)s_i(\alpha)$$

$$\tau_O=(c\cdot s_i)(\alpha)$$

를 비교하는 방법을 제안했다.

정상 항등식은 맞고 계산비용도 작다. 그러나 단일 NTT 좌표 오류에 대한 미탐률 해석은 잘못되었다.

11.2 왜 국소적인가

$q-1=64512=512\times126$이므로 $x^{256}+1$은 $\mathbb F_q$에서 256개의 근을 가진다. 이 근들은 HAETAE negacyclic NTT 좌표와 대응한다.

pointwise 결과의 NTT 좌표 $j$ 하나만 오염되었다고 하자. inverse NTT 후 오류다항식 $e_j(x)$는 NTT 평가점에서 다음 성질을 갖는다.

$$e_j(\alpha_j)\neq0$$

$$e_j(\alpha_k)=0,\qquad k\neq j$$

따라서 비밀 NTT 근 한 개를 균일하게 선택하면

$$P_{\mathrm{detect}}=\frac1{256}$$

$$P_{\mathrm{miss}}=\frac{255}{256}\approx99.61%$$

이다.

서로 다른 두 근을 선택해도

$$P_{\mathrm{detect}}=\frac2{256}\approx0.78%$$

$$P_{\mathrm{miss}}=\frac{254}{256}\approx99.22%$$

이다.

즉, 평가점당 미탐률이 $2^{-8}$인 것이 아니라 평가점당 검출률이 $2^{-8}$이다.

11.3 현재 판정

NTT 근 평가점 태그는 다음에는 보조적으로 유용할 수 있다.

전체 블록 zeroing

coefficient-domain에 넓게 확산된 오류

특정 term-drop

그러나 다음에는 주 검출기로 부적합하다.

pointwise 단일 좌표 bit flip

NTT 출력 특정 좌표 오류

inverse NTT 입력의 단일 좌표 오류

따라서 평가점 1~2개 방식은 T1 전체를 보호하는 주 검출기로 채택하지 않는다.

12. T1 검출 후보 4: 비근(non-root) 보정 다항식 fingerprint

상태: 현재 대화에서 유도된 신규 후보 / 아직 C 또는 Python 구현 검증 전

NTT 근의 국소성 문제를 피하면서 Horner 평가의 비용 장점을 살리기 위해

$$\alpha^{256}\neq-1\pmod q$$

인 비근 $\alpha$를 사용할 수 있다.

12.1 평가 함수

$$\Phi_\alpha(f)=\sum_{k=0}^{N-1}f_k\alpha^k\pmod q$$

비근에서는 단순히

$$(c\star s)(\alpha)=c(\alpha)s(\alpha)$$

라고 할 수 없다. negacyclic wrap을 명시적으로 보정해야 한다.

$$P_t=\sum_{r=0}^{t}s_r\alpha^r,\qquad P_{-1}=0$$

라고 하면 $u=c\star s$에 대해 다음 식을 사용할 수 있다.

\alpha^{j-N}\left(P_{N-1}-P_{N-j-1}\right)\right]}$$

HAETAE MODE2에서는 $c_j\in{0,1}$이므로 nonzero 위치 58개만 처리하면 된다.

기대 태그:

$$\tau_{E,i}^{(\alpha)}=\Phi_\alpha(c\star s_i)$$

관측 태그:

$$\tau_{O,i}^{(\alpha)}=\Phi_\alpha(\widetilde u_i)$$

12.2 이론적 미탐 상한

오류다항식을

$$e_i(x)=\widetilde u_i(x)-u_i(x)$$

라고 하면 태그 차이는

$$\tau_{O,i}^{(\alpha)}-\tau_{E,i}^{(\alpha)}=e_i(\alpha).$$

비영 다항식 $e_i$의 차수는 최대 255이므로, $\alpha$를 $\mathbb F_q^*$의 NTT 근이 아닌 값에서 비밀·균일하게 선택하면 한 점의 미탐확률은 보수적으로 약

\frac{255}{64256}\approx3.97\times10^{-3}$$

이하이다.

서로 독립적인 두 비근 $\alpha_1,\alpha_2$를 사용하면 보수적 상한은

$$\left(\frac{255}{64256}\right)^2\approx1.57\times10^{-5}$$

로 균일 $\rho$ 한 개의 $1/q$와 유사한 규모가 된다.

이 값은 오류다항식이 공격자에게 고정되고 $\alpha$가 비밀·독립적으로 선택된다는 조건의 확률 상한이다.

12.3 예상 비용

한 $\alpha$당 대략 다음이 필요하다.

power table 또는 Horner용 준비: 약 255 field multiplication

각 $s_1$ 블록:

sparse 기대 태그: 약 $2\tau=116$ field multiplication

세 블록 기준 한 점당 약 1,368 field multiplication, 두 점이면 약 2,736회 수준의 정적 연산량으로 추정된다.

이는 full recomputation의 약 5,632 Montgomery reduction보다 작을 가능성이 있지만, 다음 비용이 추가되므로 실측 전에는 우위를 주장할 수 없다.

$\alpha$ 파생

12.4 구현상 미해결점

$\alpha$를 NTT 근이 아닌 집합에서 constant-time으로 균일 선택하는 방법

두 $\alpha$의 독립성과 0·1·저차수 값 회피

파생 과정의 fault hardening

따라서 이 방식은 유망 후보이지만 현재 확정안이 아니다.

13. c·s 대표값 오류를 위한 범위 검사

T1 fingerprint를 mod $q$로만 계산하면 실제 coefficient가

$$u_k\longrightarrow u_k+q$$

로 오염된 경우 mod $q$ 태그에서는 같은 값으로 보일 수 있다.

그러나 원본 polyfix_add()는 cs를 다시 mod $q$로 줄이지 않고

$$z_k=y_k+L_Nu_k$$

로 사용하므로 대표값 오류도 실제 $z$에 영향을 준다.

MODE2에서는

$c$의 weight: $\tau=58$

$s_i$ coefficient: $-1,0,1$

이므로 정상 negacyclic 곱의 각 coefficient는 정수 범위

$$-58\le u_k\le58$$

안에 있어야 한다.

따라서 다음 branchless range residual을 추가하는 것이 좋다.

\bigvee_{i,k}\operatorname{violates}(-\tau\le cs_{1,i,k}\le\tau)$$

이 검사는 다음 오류를 보완한다.

$u+q$, $u-q$ 형태의 대표값 오류

reduction 스킵

비정상적으로 큰 intermediate가 coefficient-domain에 남은 경우

14. T2 보호: 결정론적 재덧셈 유지

원본 응답은

$$z_1=y_1+(-1)^bL_Ncs_1$$

이다.

이미 계산된 cs1을 재사용하여 다음을 다시 계산한다.

$$z_{1,E}=y_1+(-1)^bL_Ncs_1$$

실제 결과를

$$z_{1,O}=z_1$$

로 둔다.

T2가 없으면

$$z_{1,E}=z_{1,O}$$

이고, +y 스킵이 발생하면

$$z_{1,O}=(-1)^bL_Ncs_1\neq z_{1,E}.$$

구현은 다음처럼 전체 coefficient XOR-OR 축약으로 구성할 수 있다.

polyfixvecl_add(&z1_check, &y1, &cs1);

uint64_t dz = 0;
for (i = 0; i < HAETAE_L; ++i)
    for (k = 0; k < HAETAE_N; ++k)
        dz |= (uint32_t)(z1.vec[i].coeffs[k]
                         ^ z1_check.vec[i].coeffs[k]);

기대 transcript에는 0을, 관측 transcript에는 dz를 넣는다.

$$\Theta_E:\ d_z=0$$

$$\Theta_O:\ d_z=\bigvee(z_1\oplus z_{1,E})$$

이 방식은 다음 특성을 가진다.

c·s 전체 재계산 없음

T2에 대해 결정론적

별도 소수 modulus 충돌 없음

데이터 의존 중단 분기 없음

단, dz라는 wide residual은 존재한다. 따라서 태그 상쇄가 모든 잔차 변수를 제거한다고 주장해서는 안 된다. 제거되는 것은 최종 중앙 delta -> factor 선택이다.

15. RB 보호: 독립 노름 재검사 유지

원본 reject1, reject2 값만 transcript에 넣으면 해당 계산 자체를 zeroing하는 오류에 취약할 수 있다.

따라서 다음을 독립적으로 다시 계산한다.

$$r_{B1}=\operatorname{violates}(|z|^2<B_1^2L_N^2)$$

$$r_{B0}=\operatorname{violates}(B_0\text{ bimodal condition})$$

기대 transcript에는

$$(r_{E,B1},r_{E,B0})=(0,0)$$

을 넣고, 관측 transcript에는 독립 재검사 결과를 넣는다.

rejection 분기가 스킵되어 경계 위반 서명이 진행되더라도 $r_{B1}$ 또는 $r_{B0}$가 1이면 감염 스트림이 상쇄되지 않는다.

이 방식은 기존 IRV의 M2를 유지하는 것이다.

16. 태그 파생값 $\rho$·$\alpha$의 오류

16.1 single-fault model에서의 해석

$\rho$ 또는 $\alpha$만 zeroing·상수화되고 주 c·s가 정상이라면 즉시 키누설이 발생하지 않는다.

기대 태그와 관측 태그는 같은 퇴화된 map을 사용하므로 정상 서명은 유지될 수 있다.

또는 파생 방식에 따라 정상 서명이 감염되어 DoS가 될 수 있다.

검출기를 무력화한 뒤 주 연산도 오염시켜야 키누설 우회가 가능하므로 엄격히는 다음의 2차 오류 문제이다.

$$\text{태그 파생 오류}+\text{주 연산 오류}$$

따라서 이를 “새로운 단일 오류만으로 즉시 키가 누설된다”고 표현하면 과장이다.

16.2 그래도 하드닝이 필요한 이유

현재 연구가 탐지분기 스킵형 2차 오류 내성을 핵심으로 삼고 있으므로 태그 파생 경로도 다음 이유로 강화해야 한다.

넓은 글리치가 파생·저장 경로와 민감연산을 함께 오염할 가능성

zero-initialized 출력 버퍼에 대한 XOF squeeze 스킵

동일 함수·동일 메모리 경로의 공통모드 오류

공격자가 태그 파생 창을 먼저 무력화한 뒤 민감연산을 공격하는 다중오류

16.3 권장 원칙

$y$ 또는 seedbuf와 태그 파생 상태를 공유하지 않음

두 태그 파라미터를 서로 다른 domain으로 독립 파생

0으로 초기화된 버퍼에 단일 squeeze()만 의존하지 않음

비밀 key word를 초기상태에 직접 혼합

$\rho=0$ 또는 $\alpha\in{0,1}$을 constant-time으로 배제

두 파생 코드와 저장영역을 시간·메모리상 분리

파생 결과의 퇴화를 transcript에 보조적으로 반영

예시 방향은 다음과 같다.

raw1 = load16(key + 0);
raw2 = load16(key + 2);

raw1 ^= xof_word(DOMAIN_TAG1, key, mu, attempt);
raw2 ^= xof_word(DOMAIN_TAG2, key, mu, attempt);

XOF 호출이 스킵되어도 파라미터가 공개된 0으로 남지 않게 하는 목적이다.

64비트 곱 비용이 구현에 따라 다름

따라서 현재 결론은 다음이다.

균일 $\rho$ 방식은 두 번째 full c·s를 제거하지만, 실제 cycle 우위는 아직 입증되지 않았다.

17.3 비근 $\alpha$ 두 점 후보

정적 추정은 약 2,736 field multiplication과 add/sub이다. full recomputation보다 작을 가능성이 있으나 아직 구현 검증 전이다.

17.4 감염 XOF 두 스트림 비용

HAETAE-120 서명 길이는 1,474바이트이고 SHAKE256 rate는 136바이트이다.

한 전체길이 스트림 출력에는 약

$$\left\lceil\frac{1474}{136}\right\rceil=11$$

개의 rate block이 필요하다.

기존 IRV: 전체길이 감염 스트림 1개

태그 상쇄 구조: 전체길이 감염 스트림 2개

추가비용: 전체길이 스트림 1개 상당의 squeeze와 상태 처리

따라서 fingerprint가 절감한 비용이 두 번째 감염 스트림으로 상당 부분 상쇄될 수 있다.

논문에서는 다음처럼 표현해야 한다.

SFO-TC는 두 번째 full c·s 연산을 제거한다. 그러나 전체 실행시간이 기존 IRV보다 작다는 주장은 fingerprint, transcript, 두 감염 스트림을 모두 포함한 실측 후에만 가능하다.

18. 권장 통합 transcript

T1에 두 독립 fingerprint를 사용하는 예시로 기대·관측 transcript를 다음처럼 구성할 수 있다.

기대 transcript:

$$\Theta_E=(\tau_{E,0}^{(1)},\tau_{E,1}^{(1)},\tau_{E,2}^{(1)},\tau_{E,0}^{(2)},\tau_{E,1}^{(2)},\tau_{E,2}^{(2)},0,0,0,0)$$

관측 transcript:

$$\Theta_O=(\tau_{O,0}^{(1)},\tau_{O,1}^{(1)},\tau_{O,2}^{(1)},\tau_{O,0}^{(2)},\tau_{O,1}^{(2)},\tau_{O,2}^{(2)},d_z,r_{B1},r_{B0},r_{\mathrm{range}})$$

여기서:

$\tau^{(1)},\tau^{(2)}$: 선택된 T1 fingerprint 두 개

$d_z$: T2 재덧셈 residual

$r_{B1},r_{B0}$: 독립 노름 재검사 residual

$r_{\mathrm{range}}$: cs 대표값 범위 residual

최종 반응은 다음이다.

$$M_E=F_{K_I}(\mathrm{ctx}\parallel\Theta_E)$$

$$M_O=F_{K_I}(\mathrm{ctx}\parallel\Theta_O)$$

$$\sigma^*=\sigma\oplus M_E\oplus M_O$$

ctx에는 적어도 다음이 포함되어야 한다.

domain separator

메시지 해시 $\mu$

서명 시도 번호 또는 nonce counter

알고리즘·파라미터 식별자

21. 논문 포지셔닝

21.1 사용할 수 있는 주장

본 기법은 HAETAE의 전체 $c\cdot s$ 경로를 한 번만 수행하고, 독립 무결성 transcript에서 생성한 두 감염 스트림이 정상 실행에서 상쇄되도록 한다.

순수 응답 내부 감염은 HAETAE의 아핀 구조와 짧은 인코딩 제약으로 제한되므로, 감염 반응은 패킹 후 출력에 적용한다.

제안의 핵심은 오류를 검출한 뒤 분기하는 것이 아니라, 기대 transcript와 관측 transcript의 동일성이 정상 출력의 불변성을 직접 결정하는 태그 상쇄 반응이다.

기존 불가능성 분석이 지목한 post-encode 실현 형태를 구체화하고, 중앙 delta -> factor 선택을 제거한다.

21.2 실측 전에는 보류할 주장

기존 IRV보다 전체 실행시간이 작다.

균일 $\rho$가 full recomputation보다 확실히 저비용이다.

비근 $\alpha$ 방식이 모든 실제 fault에 대해 $1.57\times10^{-5}$ 미탐률을 달성한다.

모든 2차 오류에 안전하다.

감염 적용부에 단일 실패점이 없다.

21.3 피해야 할 표현

“무오버헤드 1회 연산 감염형”

“평가점 두 개로 모든 NTT 오류를 $2^{-16}$로 검출”

21.4 현재 가장 정확한 한 문장

HAETAE의 순수 z-내재형 오류확산이 갖는 구조적 한계를 수용하면서, 전체 c·s 계산은 한 번만 유지하고 독립 무결성 transcript와 post-encode 태그 상쇄를 결합하여 중앙 비교·중단 선택 없는 감염 반응을 구현하는 것이 현재 연구의 핵심 방향이다.
