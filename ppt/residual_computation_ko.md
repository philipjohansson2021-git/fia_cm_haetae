# IRV 잔차(δ) 계산 — 알고리즘 2 라인별 설명·예시·구현 코드

논문 **알고리즘 2(IRV 무결성 보호)**의 `δ`(펌웨어 `cm_delta`)가 어떻게 계산되는지를, 각 라인의
**뜻 → 실제 값 예시 → 구현 코드 → 동작**으로 정리한다. 근거: `haetae_sign_cm.c`, `simpleserial-haetae.c`.

---

## 0. 먼저 — 자주 하는 오해 정정

> **Q. 잔차는 원본 Sign 슈도코드를 라인별로 한 번씩 다시 실행해서 계산하나요?**
> **A. 아니요.** 그건 전체 이중연산(`double`, 2× 비용)입니다.

IRV는 **표적별 무결성 검사 6개(M1~M6)** 를 응답 `z` 확정 직후 **한 번씩** 수행하고, 각 검사의 **잔차**
(올바른 값과 실제 값의 불일치)를 하나의 누산기 `δ`에 **OR( | )** 로 모읍니다.

- **재계산은 딱 필요한 것만**: M4만 응답연산 `z=y+(-1)^b·c·s1`을 **1회** 다시 계산. 나머지는
  값 비교/재검사(체크섬·노름·재샘플)라 매우 가볍습니다. → **그래서 IRV는 1.14×**(double 2.0×의 절반).
- **OR로 모으는 이유**: 검사 중 **하나라도** 잔차≠0이면 `δ≠0` → 마스크가 서명을 통째로 난수화.
  즉 "모든 검사 통과(δ=0)"만 서명이 살아남습니다.

```
δ = Chk_M1 | Chk_M2 | Chk_M3 | Chk_M4 | Chk_M5 | Chk_M6
```

## 1. (복습) 오류 지점이 왜 취약한가

서명이 비밀키를 쓰는 유일한 연산 `z = y + (-1)^b·LN·(c·s1)` 주변의 7개 지점:

| 지점 | 오류 효과 | 왜 위험한가 |
|---|---|---|
| **T2** (+y 스킵) | `z = LN·c·s1` | y(마스크) 제거 → `z/LN=c·s1`, c 공개 → **서명 1개로 s1 100% 복원** |
| **T1** (c·s 스킵) | `z ≈ y` | 정상과 차분 `z_clean−z_fault=LN·c·s1` → s1 복원 |
| **RB** (거부 스킵) | 경계초과 z 방출 | 서명경계 B1 넘긴 z가 통계적으로 s1 누설 (B1<B2라 검증은 통과) |
| SEED (시드 스킵) | 시드=0 고정 | y가 예측가능 → 난수 노출 |
| SIGNBIT (b 반전) | 부호 뒤집힘 | 정상-오류 차분이 y를 소거 → s1 차분 노출 |
| UNPACK (A 변조) | 잘못된 공개행렬 | 잘못된 c → 차분 공격 |
| LSB (스킵) | 다른 챌린지 c | 차분 공격 |

> **용어**: 위에서 "서명 1개 / 2개 / 다수"는 공격에 필요한 **서명 출력값(z)의 개수**를 뜻한다.
> **SCA(부채널)의 전력·전자파 파형(trace)이 아니다.** "차분"도 정상 서명 출력 1개 + 오류 서명 출력 1개를 빼는 것이다.

**공통 원리**: 마스크 `y`나 챌린지 `c`나 응답 `z`의 무결성이 깨지면, 공개값만으로 비밀 `s1`이 역산된다.
IRV의 각 검사는 이 지점 하나하나를 **재계산·재검사로 되짚어** 잔차로 만든다(아래 매핑).

> 분기로 수행 — 핵심 응답검사(L2~L6)는 무분기로 δ에 누적되어 2차 오류에 강함.

## 3. 라인별 상세 — 뜻 · 값 예시 · 코드 · 동작

### L1) `δ ← 0` — 누산기 초기화
```c
uint64_t cm_delta = 0;                 // haetae_sign_cm.c:156
```
동작: 이후 모든 검사 결과를 여기에 OR로 쌓는다. 무결함이면 끝까지 0.

---

### L2) M1 — 비밀키 체크섬 (막는 오류: 영속 키변조)
**뜻**: 서명 시작 시 비밀키 `s1`의 FNV-1a 체크섬을 기준값과 비교. 키 메모리가 변조됐으면 다르다.
**코드** (`:183–185`):
```c
uint32_t ck = ck_polyvecm(&s1);              // FNV-1a 해시
if (!g_have_ck){ g_golden_ck = ck; g_have_ck = 1; }   // 첫 무결함 서명 = 기준
if (ck != g_golden_ck) cm_delta |= 1;        // 다르면 잔차
```
**값 예시**:
| | ck (해시) | 기준 golden | 잔차 |
|---|---|---|---|
| 무결함 | `0x8F3AC21D` | `0x8F3AC21D` | `0` |
| 키 1비트 변조 | `0x2B71E04A` | `0x8F3AC21D` | `δ |= 1` |

FNV-1a: `h=2166136261; 각 워드마다 h ^= word; h *= 16777619;` — 1비트만 바뀌어도 해시가 완전히 달라짐.

---

### L3) M2 — 시드 정상성 (막는 오류: SEED)
**뜻**: 시드 버퍼가 전부 0이거나 전부 같은 값이면(=시드 squeeze가 스킵됨) 결함.
**코드** (`:365–368`):
```c
int allz=1, alls=1;
for (t=0;t<HAETAE_CRHBYTES;t++){ if(seedbuf[t]) allz=0; if(seedbuf[t]!=seedbuf[0]) alls=0; }
if (allz | alls) cm_delta |= 1;
```
**값 예시**:
| | seedbuf | allz | alls | 잔차 |
|---|---|---|---|---|
| 무결함 | `3A 91 7C 08 …`(다양) | 0 | 0 | `0` |
| SEED 스킵 | `00 00 00 00 …` | **1** | 1 | `δ |= 1` |

---

### L4) M3 — (y, b) 재유도 (막는 오류: SIGNBIT)
**뜻**: 같은 시드·카운터로 하이퍼볼 샘플을 **다시 뽑아** `(y', b')`를 방출값 `(y, b)`와 비교.
부호비트 `b`만 뒤집힌 결함은 서명이 여전히 유효해 검증·곱셈재계산으로는 안 잡히므로 **별도로** 포착.
**코드** (`:369–373`):
```c
polyfixvecl y1b; polyfixveck y2b; uint8_t bb=0;
polyfixveclk_sample_hyperball(&y1b,&y2b,&bb, seedbuf, cb);   // 같은 시드·카운터 cb
if (bb!=b || memcmp(&y1b,&y1,..) || memcmp(&y2b,&y2,..)) cm_delta |= 1;
```
**값 예시** (SIGNBIT 결함):
| | 재유도 bb | 방출 b | 잔차 |
|---|---|---|---|
| 무결함 | 0 | 0 | `0` |
| b 반전 | **0** | **1** | `δ |= 1` (bb≠b) |

---

### L5) M4 — 응답 재계산 (막는 오류: **T1 / T2**) ★핵심
**뜻**: `c·s1`을 다시 곱하고 `z1b = y1 + (-1)^b·c·s1'`을 만들어 **방출 z1과 계수별 비교**.
오류는 **출력**의 y를 지웠어도 `y1`은 **메모리에 그대로**라, 재계산하면 정상값이 복원된다.
**코드** (`:350–359`):
```c
polyvecl cs1b; poly chatb=c; poly_ntt(&chatb); cs1b.vec[0]=c;
for (ii=1; ii<HAETAE_L; ++ii){                       // c·s1 재계산
  poly_pointwise_montgomery(&cs1b.vec[ii],&chatb,&s1.vec[ii-1]);
  poly_invntt_tomont(&cs1b.vec[ii]); }
polyvecl_cneg(&cs1b, b&1);
polyfixvecl z1b; polyfixvecl_add(&z1b,&y1,&cs1b);    // z1b = y1 + (-1)^b·c·s1
for (ii=0; ii<HAETAE_L; ++ii)
  for (k=0; k<HAETAE_N; k++)
    if (z1.vec[ii].coeffs[k] != z1b.vec[ii].coeffs[k]) cm_delta |= 1;   // 불일치→잔차
```
**값 예시** (계수 하나, 부록 A: y1=100, c·s1=7):
| | 방출 z1 | 재계산 z1b | 비교 | 잔차 |
|---|---|---|---|---|
| 무결함 | 107 | 107 | 같음 | `0` |
| **T2** (+y 스킵) | **7** | **107** | 다름 | `δ |= 1` |
| **T1** (c·s 스킵) | ≈ y1(=100) | 107 | 다름 | `δ |= 1` |

---

### L6) M5 — 노름 B1+B0 재검사 (막는 오류: **RB**)
**뜻**: 방출 z의 노름을 **서명경계 B1**(과 bimodal 보조경계 B0)로 다시 검사. 거부 우회로 경계 넘긴
z를 잡는다. (검증경계 B2가 아니라 **서명경계 B1**로 보는 것이 포인트 — B1<B2.)
**코드** (`:360–364`):
```c
uint64_t r1 = ((uint64_t)HAETAE_B1SQ*HAETAE_LN*HAETAE_LN - polyfixveclk_sqnorm2(&z1,&z2)) >> 63; // ‖z‖>B1 이면 1
uint64_t r2 = (polyfixveclk_sqnorm2(&z1tmp,&z2tmp) - (uint64_t)HAETAE_B0SQ*HAETAE_LN*HAETAE_LN) >> 63;
r2 &= (b & 0x2) >> 1;
if ((r1 | r2) & 1) cm_delta |= 1;
```
**값 예시** (B1=9839, B2=12777):
| | ‖z‖ | r1 (‖z‖>B1?) | 잔차 | (참고) 검증 B2 |
|---|---|---|---|---|
| 무결함 | 8500 | 0 | `0` | 통과 |
| **RB** | 10000 | **1** | `δ |= 1` | 통과(못 잡음)→ IRV가 잡음 |

---

### L7) M6 — 표준 검증 (막는 오류: LSB / UNPACK)
**뜻**: 방출 서명을 검증식으로 재구성. 자기일관적이지만 공개키와 안 맞는 서명(LSB로 다른 c,
UNPACK로 잘못된 A)을 잡는다. 스택이 커서 서명함수 밖(main)에서 수행.
**코드** (`simpleserial-haetae.c:78`):
```c
int bad = crypto_sign_verify(g_sig, g_slen, g_msg, 16, PRE, 0, pk);
if (bad) memset(g_sig, 0xFF, CRYPTO_BYTES);   // 무효화 (알고리즘2에선 δ|=Chk_M6 로 표현)
```
> 알고리즘 2는 이를 `δ |= Chk_M6`로 이상화. 실제로는 main의 분기 — 핵심 응답검사(L2~L6)는 무분기라
> 2차 오류에 강하고, L7은 상류(LSB/UNPACK) 보강용.

---

### L8) 마스크 생성 — δ를 전-0/전-1로 (무분기)
**코드** (`infect_sig`, `:133`):
```c
uint8_t factor = (uint8_t)(0u - (uint8_t)((delta | (0u - delta)) >> 63));
```
**값 예시**:
| δ | `δ | (−δ)` 최상위비트 | `>>63` | factor |
|---|---|---|---|---|
| 0 | 0 | 0 | **0x00** |
| 1 (또는 임의 ≠0) | 1 | 1 | **0xFF** |

if 없이 "δ가 0인가?"를 바이트 마스크로 변환. **버릴 분기가 없다.**

---

### L9) 감염 — 서명에 XOR
**코드** (`:135–140`):
```c
// ks = SHAKE256( 비밀시드 ‖ δ(8바이트) ‖ μ )   ← μ(메시지 해시) 결합 = 마스크 신선도
shake256(ks, HAETAE_CRYPTO_BYTES, seed, ...);
for (i=0;i<HAETAE_CRYPTO_BYTES;i++) sig[i] ^= (uint8_t)(ks[i] & factor);
```
**동작**:
- δ=0 → factor=0x00 → `sig ^= 0` → **서명 그대로** (오탐 0)
- δ≠0 → factor=0xFF → `sig ^= ks` → **서명 전체 난수화 → 검증 실패 + 키정보 0**

μ를 섞는 이유: 같은 δ가 여러 서명에서 반복돼도 마스크가 매번 달라져, 두 감염 출력의 XOR로 마스크가
상쇄되지 않도록(마스크 신선도).

---

### L10) `return σ`
감염이 끝난 서명을 반환. 무결함이면 원본과 동일, 결함이면 무효화된 난수 서명.

## 4. 전체 동작 요약 (한 문단)

IRV는 응답 `z` 확정 직후 **여섯 검사(키체크섬·시드정상성·(y,b)재유도·응답재계산·노름B1+B0·표준검증)**
를 한 번씩 수행해 각 잔차를 `δ`에 OR로 모은다. 재계산은 응답연산 1회 + 가벼운 재검사뿐이라 비용은
**1.14×**(전체 재실행 `double`의 2.0× 대비 절반). 마지막에 `factor = (δ=0 ? 0x00 : 0xFF)`라는 **분기 없는**
한 줄로 마스크를 만들어 `sig ^= PRF(비밀시드‖δ‖μ) & factor`. 결함이 **하나라도** 있으면 δ≠0 → 서명 전체
난수화. **버리는 if가 없으므로**, 그 분기를 건너뛰는 2차 오류가 성립하지 않는다.

## 5. 원본 vs IRV 라인별 비교

| 단계 | 원본 (`sign.c`) | IRV (`haetae_sign_cm.c`) |
|---|---|---|
| ① 응답 z 계산 | `cs=c·s1; z=y+(-1)^b·cs` | (동일) |
| ② 거부 판정 | `reject=‖z‖>B1 ∨ bimodal B0; if(reject) goto reject` | (동일) |
| ③ 무결성 검사 | — 없음 — | `δ ← (z ≟ y+(-1)^b·c·s1' 재계산) | (‖z‖≤B1·B0 재검사) | (시드·(y,b) 재유도)` |
| ④ 감염 | — 없음 — | `sig ^= ks & factor` (δ≠0이면 난수화) |
| ⑤ 패킹·반환 | `pack_sig; return` | `pack_sig; infect_sig(δ); return` |

핵심 연산(①②⑤)은 원본과 **바이트 동일** — IRV는 ③검사·④감염만 삽입. 그래서 무결함 서명은 원본과
동일하고(오탐 0), 비용은 응답 1회 재계산 + 가벼운 검사라 **1.14×**.

## 6. "2차 오류로 잔차·감염 연산 자체를 건너뛰면?" — 정직한 한계

두 종류의 2차 오류를 구분해야 한다.

- **모델 O — 탐지 "분기" 스킵** (논문이 주장하는 범위): IRV 핵심엔 `if` 분기가 없다
  (`sig ^= ks & factor`는 무조건 실행) → **건너뛸 분기가 없어 생존.** double·leeha는 분기 하나가
  방어 전체라 한 방에 뚫린다.
- **모델 X — 잔차·감염 "연산 자체" 표적** (잔존 위협): `δ|=1` 스킵 / `δ`를 0으로 강제 /
  `factor` 계산 스킵 / `infect_sig`의 XOR 루프 스킵 → 누설 서명이 감염되지 않고 방출 → **IRV도 뚫린다.**
  이는 "분기 스킵"이 아니라 특정 데이터 연산을 정밀 타격하는 **다른 종류의 2차 오류**다.

**그래도 IRV가 나은 점 · 논문 입장**: IRV는 가장 쉬운 단일 표적(중단 분기)을 제거해 "불리언 하나 뒤집기"를
"특정 감염 연산 정밀 타격"으로 격상시킨다. 논문의 2차 내성 주장은 **분기-스킵 모델에 한정**하며, 감염을
데이터 흐름에 직조해 이 잔존 위협까지 견디는 강건 구현은 **향후 과제(§5.6)**로 명시한다.
