## 발표 흐름 (요약)
1. HAETAE는 `z = y + c·s1` **한 줄**에서만 비밀키를 쓴다.
2. `+y`를 오류로 건너뛰면 `z = c·s1` → `c`가 공개라 **서명 1개로 키 복원**(57344÷8192=7=c·s1).
3. 기존 방어는 "다르면 버리는 **if**" → 그 if를 2차 오류로 또 건너뛰면 뚫린다.
4. **IRV**: 오류 흔적 δ를 모아 **분기 없이** 서명 감염(δ≠0→난수화). 버릴 if가 없어 2차 오류도 못 뚫음.
5. 검증경계(B2)가 아니라 **서명경계(B1)로 다시 봐서** 거부 우회(RB)까지 차단. 비용은 이중연산의 **절반**.

## 핵심 숫자 (외우면 좋은 것)
- `LN = 8192` (고정소수점 스케일; 나눗셈 무손실)
- T2 예시: 방출 `57344 ÷ 8192 = 7 = c·s1`
- 경계: **B1 ≈ 9839(서명), B2 ≈ 12777(검증), B1 < B2**
- 결과: 커버리지 IRV **7/7** vs Lee-Ha 6/7(RB 누락) · 비용 IRV **1.14×** vs 이중연산 2.0×
