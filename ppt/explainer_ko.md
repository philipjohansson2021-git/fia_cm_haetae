# HAETAE 취약점과 IRV 대응기법 — 발표 설명서 (코드·실제 값)

논문 핵심을 남에게 설명하기 위한 자료. 순서: **① 용어 → ② 급소 한 줄 → ③ baseline 취약 코드 →
④ 공격이 통하는 이유(실제 값) → ⑤ IRV가 코드로 막는 법(실제 값) → ⑥ RB와 두 경계(B1<B2) 상세 →
⑦ 왜 double·Lee-Ha보다 나은가 → ⑧ 30초 대본**.

파라미터(HAETAE-120 / MODE2): `q=64513, LN=8192(=2^13), N=256, L=4, M=L-1=3, K=2, η=1`.
비밀키 `s1` = 다항식 3개 × 256계수 = **768개의 삼진수 {-1,0,1}**.

---

## 0. 용어 정리 (먼저 읽기)

| 용어 | 뜻 |
|---|---|
| **응답 `z`** | 서명이 내보내는 값. `z = y + (-1)^b·c·s1`. 비밀키를 쓰는 유일한 연산. |
| **`y` (nonce)** | 일회용 난수. 매 서명마다 달라 비밀신호를 가리는 **마스크**. |
| **`c` (챌린지)** | 해시로 만든 공개 다항식. **서명에 같이 실려 공개**됨. |
| **`s1` (비밀키)** | 복원 표적. 768개 삼진수. |
| **`b` (부호비트)** | bimodal 부호(0/1). `(-1)^b`로 `c·s`의 방향을 뒤집어 거부율을 낮춤. |
| **`LN=8192`** | 고정소수점 스케일 상수. 정수 나눗셈으로 정확히 되돌릴 수 있음(무손실). |
| **노름 `‖z‖`** | 벡터 `z`의 "크기"를 하나로 요약한 값 = √(Σ 계수²). `z`가 크면 비밀 정보가 샘. |
| **거부 샘플링** | 서명자가 위험한(큰) `z`를 **버리고 새 `y`로 다시 뽑는** 과정. |
| **서명경계 `B1`(≈9839)** | 서명자 기준: `‖z‖>B1`이면 **버린다**. 목적 = **비밀 보호**(빡빡). |
| **검증경계 `B2`(≈12777)** | 검증자 기준: `‖z‖≤B2`이면 **유효 인정**. 목적 = **위조 방지**(느슨). |
| **T1** | 오류지점: `c·s` 곱셈 스킵 → `z≈y`(난수 노출). |
| **T2** | 오류지점: `+y` 덧셈 스킵 → `z=c·s1`(비밀 직접 노출, 가장 치명). |
| **RB** | 오류지점: 거부 검사(if) 스킵 → 원래 버려야 할 큰 `z` 방출(통계적 누설). |
| **2차 오류** | 대응기법의 "검사 후 버리는 if"를 **또 한 번** 오류로 건너뛰는 공격. |
| **IRV** | 제안 대응기법. 오류 흔적을 숫자 `δ`에 모아 **분기 없이** 서명을 감염(무효화). |

## 1. 급소는 딱 한 줄

서명이 비밀키를 쓰는 **유일한 연산** (`haetae_sign_cm.c:263–314`):
```
z1[i] = y1[i] + (-1)^b · LN · (c·s1)[i]
        └마스크┘   └────── 비밀 신호 ──────┘
```
정상 서명은 `y1`이 신호를 가려 `s1`이 안 보인다. 이 줄의 두 부분(`c·s1` 곱, `+y1` 덧셈)에
오류를 넣으면 마스크가 깨진다.

## 2. baseline(무방어) 취약 코드

```c
// c·s1 곱셈 (T1 표적)  line 263-269
cs1.vec[0]=c; chat=c; poly_ntt(&chat);
for (i=1;i<HAETAE_L;++i){ poly_pointwise_montgomery(&cs1.vec[i],&chat,&s1.vec[i-1]);
                          poly_invntt_tomont(&cs1.vec[i]); }
// +y1 덧셈 (T2 표적)   line 313
polyfixvecl_add(&z1, &y1, &cs1);       // z1 = y1 + (-1)^b·LN·c·s1
```
오류의 논리적 효과(코드 모델):
```c
// T2 = +y 스킵 : y 대신 0 → z = LN·c·s1  (line 308-310)
polyfixvecl yz; memset(&yz,0,sizeof(yz)); polyfixvecl_add(&z1,&yz,&cs1);
// T1 = c·s 스킵 : 곱을 0 → z ≈ y        (line 273-275)
for (ii=1;ii<HAETAE_L;++ii) memset(&cs1.vec[ii],0,sizeof(poly));
```

## 2b. 표 1 — 오류지점별 누설정보와 이용 (논문 §3.4)

모든 공격의 본질은 **마스크 y를 제거해 `c·s1`을 노출**시키는 것. `c`는 공개이므로 `c·s1`만 얻으면
`ŝ1 = NTT(z̃)·ĉ⁻¹`로 s1 역산.

| ID | 오류효과 | 누설정보 | 추출 | 서명 출력 수 | 출처 |
|---|---|---|---|---|---|
| SEED | 시드=0 → y 예측가능 | 난수 y | s1 | 1 | Lee-Ha |
| SIGNBIT | 부호 b 반전 | s1(차분) | s1 | 2 | Lee-Ha |
| UNPACK | 공개행렬 A 변조 | s1(차분) | s1 | 2 | Lee-Ha |
| LSB | LSB 스킵 → 다른 c | s1(차분) | s1 | 2 | Lee-Ha |
| **T1** | c·s 스킵 → z≈y | 난수 y | s1 | 2 | 본 논문 |
| **T2** | +y 스킵 → z=c·s1 | s1 직접 | s1 | **1** | 본 논문 |
| **RB** | 거부 스킵 → 경계초과 z | 통계적 키정보 | s1 통계 | 다수 | 본 논문 |

> **용어**: 여기서 **‘서명 출력 수’ = 공격에 필요한 서명 결과값(서명 z)의 개수**이다.
> **부채널분석(SCA)의 전력·전자파 파형(trace)이 아니다.** 예: "2"는 정상 서명 1개 + 오류 서명 1개를
> 받아 차분한다는 뜻(파형 2회 측정이 아님). T2가 강력한 이유도 **서명 출력 1개**로 끝나기 때문.

**그룹 A(차분 계열 — SEED·SIGNBIT·UNPACK·LSB)**: 같은 nonce의 정상+오류 두 서명 차분에서 y가 상쇄.
- SEED: 시드=0이라 y를 재현 → `z−y=(-1)^b·LN·c·s1` → s1.
- SIGNBIT: `z_n−z_f = 2·(-1)^b·LN·c·s1`(y 상쇄) → s1. (부호 뒤집힌 서명도 유효해 검증으론 못 잡음)
- UNPACK/LSB: 오류가 **다른 챌린지 c′** 유도 → `z_n−z_f=(-1)^b·(c−c′)·s1`(y 상쇄, c−c′ 공개) → s1.

**그룹 B(응답 직접 — 본 논문)**:
- T1: `z_f≈y`로 **난수 노출** → 정상과 차분 → `LN·c·s1` → s1.
- **T2**: `z_f=(-1)^b·LN·c·s1`로 **y를 아예 제거** → 서명 1개로 `z_f/LN=±c·s1` → **768계수 100% 복원**(가장 치명).
- RB: 거부 샘플링(=z 분포를 s1과 무관하게 하는 장치)을 무력화 → 경계초과 z의 분포가 s1에 의존 →
  다수 서명 **통계 분석**으로 누설. 검증경계 B2가 느슨해(B1<B2) 이런 z도 검증은 통과.

**"y를 어떻게 처리하나"로 보는 4가지**: ① 알아낸다(SEED·T1) ② 차분으로 상쇄(SIGNBIT·UNPACK·LSB)
③ 아예 없앤다(**T2**, 1개) ④ 은닉장치(거부)를 무력화(RB, 통계). y가 사라지면 `±LN·c·s1`만 남고 c 공개로 즉시 s1.

## 3. 공격이 통하는 이유 — 계수 하나, 실제 값

`y1=100`, `c·s1=7`, `(-1)^b=+1`, `LN=8192`:

| | 정상 | T2 오류(+y 스킵) |
|---|---|---|
| 방출 `z1` | `100 + 8192·7 = 57444` | `0 + 8192·7 = 57344` |
| 공격자가 보는 것 | `y` 섞여 `s1` 안 보임 | **`57344 / 8192 = 7 = c·s1`** ← 노출! |

`c`가 공개이므로 NTT 디컨볼루션으로 `s1` 역산:
```
ŝ1[k] = NTT(z1/LN)[k] · ĉ[k]^(-1) (mod q),   ĉ = NTT(c)
```
→ **오류 서명 단 1개로 768계수 100% 복원**(레퍼런스 산술과 비트단위 일치).
비결: T2의 `z`는 LN의 **정확한 배수**(57344=8192·7)라 나눗셈이 무손실. 정상 `z`는
`57444 mod 8192 = 100 ≠ 0`이라 안 됨.

**T1**은 반대로 `z≈y`(난수)를 노출 → 정상과의 **차분** `z_clean−z_fault = LN·c·s1`로 같은 복원.

## 4. IRV가 코드로 막는 법 — 실제 값

**철학**: "검사해서 다르면 버린다(if)"가 아니라, 오류 흔적을 숫자 `δ`에 모아 **분기 없이** 서명을 감염.
`δ=0`이면 서명 그대로, `δ≠0`이면 서명 전체 난수화.

### 4.1 M4 — 응답 재계산·비교 (`haetae_sign_cm.c:348–359`)
오류는 **출력**의 `y`를 지웠지만 `y1`은 **메모리에 그대로**다. 그래서 다시 계산하면 정상값이 나온다:

| | 방출 `z1` | IRV 재계산 `y1+c·s1` | 잔차 |
|---|---|---|---|
| 무결함 | 107 | 107 | `107 ^ 107 = 0` |
| **T2** | **7** | **107** | **`7 ^ 107 = 108 ≠ 0`** |

(위는 논문 부록 A의 LN 생략 예. 실제 펌웨어는 불일치 시 `cm_delta |= 1`로 둠 — 값이 1이든 108이든 δ≠0.)

### 4.2 무분기 마스크 — if 없는 한 줄 (`:133,140`)
```c
factor = (uint8_t)(0u - (uint8_t)((delta | (0u-delta)) >> 63));  // δ=0→0x00, δ≠0→0xFF
sig[i] ^= ks[i] & factor;                                        // ks = SHAKE256(비밀시드‖δ‖μ)
```
- **δ=0**: `0|(0-0)=0` → `>>63=0` → `factor=0x00` → `sig ^= 0` → **그대로**(오탐 0)
- **δ≠0**(예 δ=1): `1|(-1)` 최상위비트=1 → `>>63=1` → `factor=0xFF` → `sig ^= ks` → **서명 전체 난수화**
  (검증 실패 + 키정보 0). 공격자가 노린 `z=c·s1`이 그대로 방출되지 못함.

**핵심**: 버리는 `if`가 없다. 마스크는 **항상** 실행되고 `factor`(0/0xFF)만 갈린다.

## 5. RB와 두 경계(B1<B2) — 상세

### 5.1 왜 경계가 두 개인가 (핵심)
`z = y + c·s`의 경계는 **목적이 다른 둘**이다:

| 경계 | 값 | 누가 | 목적 |
|---|---|---|---|
| **B1**(서명경계) | ≈9839 | 서명자 | **비밀 보호** — `‖z‖>B1`이면 **버리고 새 y로 재시도**(빡빡) |
| **B2**(검증경계) | ≈12777 | 검증자 | **위조 방지** — 압축·힌트 오차 감안해 조금 **느슨** |

→ 목적이 달라 값이 다르고 **설계상 `B1 < B2`**(HAETAE의 정상 구조, 버그 아님).
정상 서명은 서명자가 B1로 다 거르므로 **`B1<‖z‖<B2`인 서명은 존재할 수 없다.**

### 5.2 그 틈이 RB의 표적
서명자의 거부 지점(`haetae_sign_cm.c:321,334`):
```c
reject1 = ((B1²·LN²) − ‖z‖²) >> 63;   // ‖z‖>B1 이면 reject1=1
if (reject1 | reject2) goto reject;    // ← RB: 이 줄을 오류로 스킵
```
`‖z‖=10000`인 `z`(9839<10000<12777)를 예로:
- 정상: `10000>B1` → 버림(재시도). 안 나옴.
- **RB**: 위 `if`를 스킵 → 이 `z`가 방출됨.
- **검증(B2=12777)**: `10000<12777` → **통과**(정상 서명처럼 보임) → 하지만 `‖z‖>B1`이라 **통계적으로 `s1` 누설**.

### 5.3 왜 Lee-Ha는 못 잡고 IRV는 잡나
- **Lee-Ha(서명후검증)**: 표준 검증은 **B2**로 봄 → `10000<12777` → 통과 → **못 잡음**.
- **IRV(M5, `:361`)**: 검증경계가 아니라 **서명경계 B1**로 재검사:
  ```c
  uint64_t r1 = ((uint64_t)HAETAE_B1SQ*HAETAE_LN*HAETAE_LN − polyfixveclk_sqnorm2(&z1,&z2)) >> 63;
  if ((r1|r2)&1) cm_delta |= 1;        // 10000>9839 → r1=1 → δ≠0 → 감염
  ```

**비유**: 공장(서명자)은 불량기준 **±0.1mm(B1)**로 엄격, 출하검사(검증자)는 **±0.5mm(B2)**만 봄.
누가 공장검사를 꺼버리면 **0.3mm 제품**(B1 초과·B2 이내)이 출하검사를 통과해 나감. 출하검사만 다시
해봐야(Lee-Ha) 못 걸러내고, **공장기준(B1)으로 다시 재야(IRV)** 걸린다.

## 6. 왜 double·Lee-Ha보다 나은가

| | baseline | double | leeha | **IRV** |
|---|---|---|---|---|
| 방식 | 무방어 | 두 번 계산 후 **`if 다르면` 버림** | 서명 후 **`if 검증실패면` 버림** | δ → **무분기 감염** |
| 커버리지 | 0/7 | 7/7 | **6/7 (RB 놓침)** | **7/7** |
| RB 차단 | ✗ | ✓ | **✗ (B1<B2 사각)** | ✓ (M5) |
| 2차 오류 | — | **우회됨** | **우회됨** | **생존** |
| 서명시간 | 1.0× | **2.0×** | 1.14× | **1.14×** |

### 6.1 2차 오류가 double/leeha를 뚫는 이유
둘은 `main`에서 **버리는 if**로 막는다 (`simpleserial-haetae.c:60,69`):
```c
if (mism) memset(g_sig,0xFF,...);   // double
if (bad)  memset(g_sig,0xFF,...);   // leeha
```
→ **2차 오류로 이 `if` 한 줄을 건너뛰면** 무효화가 실행되지 않아 **누설 서명 그대로 방출**.
IRV엔 버릴 if가 없다(`sig ^= ks & factor`는 항상 실행) → 2차 오류 성립 불가.
실측(2026-06-30): double·leeha 우회(LEAK), **IRV만 차단**.

### 6.2 비용
double은 서명 통째로 2번 → **2.0×**. IRV는 응답 재계산 1회 + 상수시간 검사 → **1.14×**(절반 미만).
대신 코드/RAM은 검증루틴(~6KB) 때문에 double보다 큼 → "서명시간·2차내성 ↔ 코드/RAM" 트레이드오프.

## 7. 발표 30초 대본

> "HAETAE는 `z = y + c·s1` 한 줄에서만 비밀키를 씁니다. `+y`를 오류로 건너뛰면 `z=c·s1`이 되고,
> `c`가 공개라 서명 **한 개**로 키가 복원됩니다 (예: 57344 ÷ 8192 = 7 = c·s1).
> 기존 방어는 '두 번 계산해 다르면 버린다'인데, 그 **버리는 if를 2차 오류로 또 건너뛰면 무력화**됩니다.
> 우리 IRV는 오류 흔적을 숫자 δ에 모아 **δ≠0이면 서명을 통째로 난수화**합니다 — `factor`(δ=0→0x00,
> 아니면 0xFF)라는 **분기 없는 한 줄**로요. 버릴 if가 없으니 2차 오류도 못 뚫고, 검증경계가 아니라
> **서명경계로 다시 봐서**(B1<B2) 거부 우회까지 잡습니다. 비용은 이중연산의 절반입니다."
